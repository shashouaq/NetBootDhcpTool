## Product Requirements

- Authors shown in title/about/readme: Joel & Codex, contact 1406829360@qq.com.
- Main use case is isolated field debugging through a selected Ethernet adapter.
- Workspace root: `D:\project\NetBootDhcpTool`.
- Release script: `build\publish.ps1`.
- Release output: `release\NetBootDhcpTool-v<version>` and `release\NetBootDhcpTool-v<version>.7z`.
- Default adapter selection should prefer connected physical Ethernet, then other physical adapters, then virtual adapters.
- Show all enumerable adapters in the UI, but block unsafe DHCP startup by policy.
- DHCP startup must remain guarded by isolated-network confirmation.
- DHCP and manual IPv4 writes always reject WLAN; legacy `AllowDhcpOnWifi` JSON is ignored and grants no authorization. Virtual and disconnected adapters remain blocked, while a real default gateway requires the separate `AllowDhcpOnAdapterWithGateway` gate. Adapter restart and MAC changes retain their independent explicit allow-any-adapter settings.
- Treat `0.0.0.0` gateway as no usable gateway.
- Do not set the host adapter default gateway to its own DHCP server IP.
- Adapter restart is a selected-adapter operation implemented as disable/enable. The UI may target wireless, virtual, disconnected, or other adapters only when the corresponding settings switch is enabled; the action requires confirmation and logs identity/result. For Windows administrative state, read `Get-NetAdapter.AdminStatus`, not link `Status`; resolve by interface index plus stable GUID, pass the verified Cim adapter as `-InputObject` to Enable/Disable-NetAdapter, and confirm the requested AdminStatus after each transition.
- MAC changes support validated manual input and locally administered random MAC generation. Each adapter's original MAC is captured before the first change in a session; the per-change restore checkbox defaults on and restoration runs only during normal application exit. Forced termination/crash restoration is not guaranteed.
- If the client DHCP request times out, tell the user to renew IP, disable/enable the client adapter, unplug/replug the client cable, restart the client network service or device, and check cable/switch/link lights.
- DHCP protocol state (`Assigned`, `Released`, `Declined`, `Expired`), UI session history, and Ping reachability are separate. Ping must not overwrite lease state; historical rows must not be probed, and a new binding/session or reused IP must not inherit an older holder's Ping state. Released, declined, and expired rows clear current Ping/HTTP/HTTPS probes while preserving last-online time. Update last-online only on unreachable-to-reachable transitions.
- Runtime logs should include bilingual explanations for common events so Chinese users can understand packet, adapter, timeout, and cleanup steps.
- Future changes must prioritize Chinese/English bilingual support for all user-visible UI, dialogs, status messages, logs, help text, and maintenance documentation; add language-resource keys instead of hardcoding one language when practical.
- Every application button, including buttons created at runtime, must have a separate compact round `?` help button beside it. Keep it small and visible by default; hovering the action or indicator shows contextual bilingual guidance, while clicking `?` opens the same explanation and never triggers the neighboring business action. Use `HelpButtonService` for new controls.

## JSON Persistence and Recovery

- Storage callers must distinguish a missing file, a valid empty value, valid primary data, recovery from a valid backup, and read/parse failure. Only a confirmed missing file may trigger file defaults. A failed load remains read-only and must never be saved as an empty collection or defaults during startup, import, or exit.
- Validate the main file and backup before replacing either. If both fail, preserve their exact contents and refuse writes; if the backup is valid, retain it while installing the recovered primary. Surface the source and failure to the user where an operation can be blocked.
- Personal favorite passwords remain protected with current-user Windows DPAPI in the primary and verified backup. Public manufacturer presets may use plaintext only when marked public; exported favorites contain no credentials. When protected data cannot be decrypted, preserve the favorite's other fields and ask for credential re-entry.
- An unreadable static-route recovery journal is not equivalent to an empty journal. Preserve it, warn the user, and lock route apply/cleanup until the record is readable; removal from Recovery Center must also recheck that write guard.
- Temporary DHCP firewall rules use a separate durable session journal. Persist the unique rule name, session owner marker, executable path, direction, UDP ports, selected interface alias, and unverified intent before each system write; only exact readback records the firewall instance ID. Never adopt a same-display-name rule. Cleanup targets one exact Name, verifies its owner marker, instance ID when known, direction/action/profile/protocol/ports/program/interface, then verifies absence. Missing is idempotent; changed or ambiguous rules keep their journal entry. An unreadable journal locks DHCP startup and cleanup. Resolve stale entries in Recovery Center before starting another DHCP session; real acceptance requires an explicitly designated isolated test interface.

## Network Workflow Ownership

- DHCP start/stop, manual apply-and-scan, adapter restore/rollback, route apply/cleanup, adapter restart/MAC change, and Recovery Center restore share the in-process `NetworkWorkflowCoordinator`. A workflow must acquire the owner lease before it writes; DHCP stop is the only workflow allowed while the DHCP service is already running. T05/T06/T08 changes must reuse this gate.
- Cancel and Escape signal only the current owner's token. Any rollback or cleanup after a system change uses an independent token and must finish before the owner releases. Window close cancels the active owner, waits for its completion, then runs normal exit cleanup.
- F5 and Ctrl+R cannot start adapter refresh during a network workflow. External refreshes are skipped while a workflow owns adapter state; internal post-change reads run under the current workflow. Busy-state helpers must not replace or cancel an existing owner's token.
- Recovery Center remains viewable in read-only mode, but its execution method checks the Safety Guide unlock again after the confirmation UI. Confirmation alone cannot bypass read-only mode or an active operation. Buttons reflect these rules, and direct handlers enforce them too.
- A canceled manual apply/scan restores a partially applied adapter snapshot before releasing the workflow; canceling only the scan phase keeps the successfully applied temporary address and its recovery snapshot, matching the existing manual-scan contract. Before a MAC write, persist an in-flight recovery record even when the final normal-exit checkbox is off; after verified success, reduce the record to the user's checkbox choice. MAC write errors/cancellation use an independent bounded restore and readback; failed compensation retains a durable Recovery Center record. Failed/canceled adapter restart restores the original administrative state; a successful restart intentionally ends enabled.
- Before DHCP or manual IPv4 writes, persist a complete snapshot of DHCP state, all IPv4 addresses and SkipAsSource flags, default routes including protocol/policy store, DNS source/value, metric mode/value, and adapter administrative state. Mark the mutation attempted before invoking PowerShell. On failure/cancellation, restore and fully recapture under an independent 30-second compensation token; a mismatch or compensation error keeps recovery pending. Unknown legacy DNS source must never be guessed.

## Network Profile Semantics

- Capture DHCP server/mask/pool/gateway/DNS/lease, manual scan range, and route inputs in profiles. Loading only fills forms; it never mutates adapter, DHCP, or route state.
- Empty optional DHCP gateway/DNS fields reset text and visibility. Save, load, and import explain whether each profile section is draft or effective; DHCP and route actions use the shared profile validators, and manual scans use ScanRangePlan.
- Compare all effective DHCP/manual-scan fields and normalized route targets as an order-independent multiset. Reject duplicate route targets rather than collapsing them. Normalize masks and CIDRs, prefer adapter ID with MAC/name relocation fallback, and recalculate interface metrics at preview time.

## Implementation Lessons

- Some Windows pseudo interfaces throw `NetworkInformationException 10043` from `GetIPv4Properties`; skip only that adapter and keep enumerating.
- Windows PowerShell may display UTF-8 logs incorrectly unless files are created with UTF-8 BOM.
- `dotnet publish` can leave files locked if the GUI or verifier is still running; always run `build/stop-test-processes.ps1` before publish/clean.
- `build/verify-dhcp-pktmon.ps1` stops any active machine-wide PktMon capture and removes global filters before its diagnostic, then stops the capture and removes filters in `finally`. Run it only when replacing existing host PktMon state is authorized. Packaging and test-process cleanup leave machine-wide PktMon captures/filters untouched.
- A GUI process launched during Codex testing can make the IDE show `timeout waiting for child process to exit`; close/kill test GUI processes before returning.
- Hyper-V may bind DHCP on `172.22.32.1:67`; log UDP receive details and verify actual DHCP traffic reaches this tool.
- DHCP `Discover` then `Request` can produce Offer and ACK events for one client. A pending Offer is not a committed lease. Key binding identity by client identifier when present, otherwise MAC; dedupe renewals within one lease/session while preserving released/expired history. Serialize lease UI updates and only probe current unexpired bindings.
- If logs show repeated `Discover` and `Offer` but no `Request`/`Ack`, the client did not accept or receive the Offer. On multi-NIC Windows hosts, limited broadcast `255.255.255.255` can leave through the wrong adapter; also send DHCP replies to the selected subnet broadcast address and log reply targets.
- Implement only the isolated IPv4 DHCP states in T09: Discover/Offer, SELECTING, INIT-REBOOT, renewal/rebinding, RELEASE, DECLINE, and expiry. Ignore a Request selecting another server; NAK invalid in-scope addresses; match the active client identity/address before renew or release. Persist the lease table before sending ACK, retain unexpired bindings and declined-address quarantine across service restarts, and fail closed when the journal is unreadable or a restored binding no longer fits the configured pool. If a lease-table commit fails while serving a packet, stop DHCP before processing another request so no later Offer or ACK can be issued from uncertain persistence state.
- Existing-DHCP detection must use one total timeout and accept only a valid Offer matching UDP source port 67, selected interface, transaction ID, client hardware address, message type, server identifier, and offered address. Ignore malformed/unrelated packets while continuing to receive. Loopback protocol checks do not establish real-client or cross-interface acceptance.
- Last online time should update only when a host transitions to reachable online, not on every ping tick.
- Ping latency should keep probing assigned/offline leases until they become reachable; once online, continue low-cost periodic ping and update last-online only on offline-to-online transition.
- Manual IP scan should not set gateway or DNS; only configure local IP and subnet mask, then scan either the target IP or the whole subnet.
- Manual scan and favorites actions must disable/highlight by workflow state to prevent duplicate scans or applying favorites while a scan is running.
- Favorites "Load configuration" only populates the manual-scan fields and records usage; "Apply and scan" reuses that population step and performs one configuration plus one scan. Keep this separation and do not add a second scan or second configuration pass.
- Favorites require at least name, IP, and mask; optional device/account/memory/custom fields can be added or removed without blocking required network use.
- Favorite lifecycle: keep deletion tombstones for shipped presets in `favorite-presets.json`; startup may add missing defaults but never overwrite an existing entry. Restore presets only through an explicit confirmation. Edit a clone and replace the row only after one successful save; preserve ID, created/last-used values, and local-only data. Imported empty values preserve local values; custom fields merge by case-insensitive stable name. Treat external `IsPublicDefault`/`PublicPassword` as untrusted and persist any imported password as a personal DPAPI credential. `SaveCredentialFreeExport` clears `Password`, `ProtectedPassword`, and `PublicPassword`, and also removes the public-default marker. Never show credential values in import previews.
- DHCP recovery must stay bound to the stable `NetworkInterface.Id` and the exact pre-change snapshot. Before starting, resolve the selected adapter from a fresh enumeration and verify its interface index still belongs to that ID after snapshot capture and before modification. Before automatic restore, uniquely resolve the original adapter from a fresh enumeration and confirm its full IPv4 state still matches the state owned by that DHCP session. Never fall back to the currently selected adapter or enable DHCP when its snapshot is missing. A successful stop restore is idempotent; when stop-time restore is unchecked, normal exit retries each pending session. Adapter loss, identity ambiguity, external changes, or restore failure retain the saved recovery item for explicit Recovery Center handling. Do not restore merely because the window opened.
- Manual scan should not set DNS. A favorite may include a target IP; when target IP is present, applying the favorite scans only that peer, and full subnet scan is used only when target IP is empty.
- Manual scan should not set gateway either. In target-IP mode, show an immediate configured row and keep pinging until the target becomes reachable or the user stops the scan.
- Manual scan inputs use `ScanRangePlan` for the same IPv4, contiguous-mask, target, host-count, and subnet rules before any adapter write. Empty target alone means subnet scan; reject invalid nonempty targets. Subnet scans exclude the local address and network/broadcast for prefixes through `/30`, probe the other `/31` endpoint, and have no implicit peer for `/32`. Reject more than 4096 actual targets before adapter writes. Keep enumeration lazy and bounded by scan concurrency; bound cancellable DNS resolution. Local tests do not establish real network acceptance.
- DHCP and manual IPv4 configuration must touch only the user-selected non-WLAN debug adapter, keep it without gateway/DNS, and force a high IPv4 metric such as 9000.
- Never modify WLAN/Wi-Fi/Wireless/无线 adapters as part of DHCP or manual scan setup. The separately-confirmed restart and MAC features may target them only when their settings switches are enabled.
- Never write WcmSvc coexistence policy keys or `CurrentVersion\\Policies\\WcmSvc` keys from this tool.
- Never run `netsh wlan connect` from this tool.
- Before DHCP start, run read-only WLAN preflight checks for current WLAN connection, USB wired NIC presence, and recent `WLAN-AutoConfig` policy-blocked auto-connect events; if found, point users to `docs/troubleshooting/windows-wifi-wired-conflict.md`.
- PowerShell and `netsh` child-process output must use UTF-8 to avoid Chinese mojibake in logs.
- Bottom log panel should show concise summarized operation results; avoid dumping full PowerShell scripts unless an unexpected unparsed failure occurs.
- Default startup must request administrator through the application manifest instead of showing a custom elevation prompt every run. Only warn if admin privilege is unavailable.
- Favorites should support JSON import/export, include BMC management-port presets for common server vendors, and merge imports without overwriting unrelated field notes.
- Manufacturer-published BMC presets are marked as public defaults and may show documented plaintext credentials; model-dependent values must point to the chassis label/manual. Personal favorites continue to use DPAPI on disk, and credential-free export remains available.
- Adapter summary should show both current IP and the previous IP after the tool changes an adapter address; restore original IP should be enabled by default.
- Favorite grids must remain read-only when binding computed fields such as CustomFieldsSummary; otherwise WPF may throw a TwoWay binding exception when the user clicks the cell.
- Grid headers should switch by language instead of showing bilingual labels simultaneously. Favorite columns should support drag reorder and a checkbox-based show/hide dialog.
- Keep `Defaults.cs`, `i18n\zh-CN.json`, and `i18n\en-US.json` key sets identical; use a lightweight key-set audit before handoff.
- DHCP gateway and DNS should be optional hidden fields by default; do not emit router/DNS DHCP options unless the user explicitly adds values.
- DHCP service must receive only on the stable selected adapter ID/index: use Windows IPv4 interface-list filtering and packet-info interface validation while retaining `0.0.0.0` client Discover support. Bind UDP to the validated selected `ServerIp`, not the wildcard, so a listener bound to a different local address (such as WSL SharedAccess) can coexist without `ReuseAddress`; a real peer on the selected physical NIC verified 0.0.0.0-sourced Discover/Request. Set the IPv4 outgoing interface on the same socket for all Offer/Ack replies, revalidate the adapter/address during service, and stop on identity/index/address loss. Firewall rules must target the selected interface alias. A local loopback smoke is not dual-interface acceptance.
- Switching between Auto DHCP and Manual IP/Scan should remind the user to click Refresh and re-confirm adapter state before continuing.
- Open/close operations should show a wait overlay so users know adapter cleanup or startup enumeration is still running.
- Update manifests carry `releaseNotes` and `changes` from the current version section of `docs/FEATURE_CHANGELOG.md`, falling back to `Unreleased` only when that version section is absent. Clicking a validated new-version link shows those changes and downloads the archive in the background without installation; the archive is checksum-verified and a sustained below-3-KB/s-for-10-seconds condition only displays the author email.
- Primary UI controls, cards, dialogs, inputs, and containers use rounded corners while virtualized DataGrid surfaces retain their performance-oriented template.
- WPF `ApplicationIcon` must point to a real ICO saved by `Icon.Save`; PNG bytes inside an `.ico` file can make resource compilation fail.
- UI language resources and XAML labels must be checked for mojibake before release, especially Chinese strings edited through PowerShell.
- On exit, persist favorites before cleanup starts, and never delete/overwrite favorites or runtime logs as part of close flow.
- Favorites and logs must use a durable per-user path (`%LOCALAPPDATA%\NetBootDhcpTool`) with one-time migration from legacy app-folder data.
- Static routes are session-owned: accept multiple IPv4/IPv6 destination addresses or prefixes, normalize host bits to the network boundary, treat a bare IPv4/IPv6 address as `/32` or `/128`, use a blank gateway for direct routes (`0.0.0.0` or `::` at the Windows API boundary), and require a gateway to match the destination address family for next-hop routes.
- The static-route page separates new editable rules from the current read-only route table, which displays all existing IPv4/IPv6 routes across local interfaces including Local/DHCP/virtual-interface routes with protocol labels; it does not require the top adapter selection and does not automatically apply anything.
- For a large existing-route set, keep the route grid display template lightweight: show the adapter name as text and create the adapter ComboBox only in `CellEditingTemplate`; retain row/column virtualization and recycling. A local frontend run with 47 routes measured 339 ms for the first route-tab render and 27 ms on repeat after this change.
- Static route application may target any identified local adapter for this feature, without changing the DHCP, scan, restart, or MAC-operation safety boundaries. Do not overwrite a matching route; the same normalized prefix may be added on different adapters but is rejected twice on one adapter, with route metrics automatically calculated from interface metrics and a deterministic effective winner. Gateways must be on-link for the selected address family/interface, more-specific existing or planned conflicts block broader rules, overlapping prefixes are previewed by longest-prefix behavior, and IPv4/IPv6 default routes are rejected.
- Record every route created by this process with adapter identity, interface index, next hop, metric, policy store, and instance ID. On exit remove only those recorded routes; after each verified deletion, commit that one record removal before continuing. Cancellation, adapter identity changes, or journal-save failure preserve every unprocessed/uncertain record for retry.
- Persist an unverified route-creation intent before `New-NetRoute`; only a successful parameter/instance-ID readback upgrades the record to verified ownership. If creation/readback/journal commit fails before ownership can be proved, retain the intent and block automatic deletion. Existing journal rows with no `OwnershipVerified` property keep the legacy verified default, but a missing instance ID still blocks cleanup. Route deletion must assign the saved policy store in PowerShell, verify exact instance/path/metric/store, treat an already-absent route as idempotent success, and verify that the owned instance is gone after deletion.
