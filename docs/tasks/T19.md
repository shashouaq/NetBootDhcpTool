## 2026-09-28 当前架构与验收

GitHub-hosted Windows runners now own CI, one-time package build/signing, GitHub Release and public asset integrity verification. Gitee mirroring runs independently through scripts/Publish-GiteeMirror.ps1 and can resume from the already-published GitHub Release. Before a Gitee Release is created, the mirror verifies the GitHub tag commit, advances Gitee main only by fast-forward, synchronizes the exact tag, and reads that tag back. A Gitee failure does not fail or roll back GitHub Formal Release. Clients probe/download only a source whose signed manifest matches the selected formal version, archive filename and SHA-256.

## 目标

保留 GitHub-hosted Windows CI 负责 PR 和日常提交验证。正式 Release 只在精确提交的 Windows CI 通过后，由国内 Windows x64 self-hosted Runner 执行。Runner 对同一标签只构建一次现有 `.7z` 包，并把相同归档和 SHA-256 sidecar 分别上传 GitHub、Gitee。客户端保持现有 `.7z` 格式以及 GitHub/Gitee 实时测速选择。

## 实现范围

- 正式发布从 `release.published` 自动同步改为 `workflow_dispatch`。GitHub-hosted 门禁确认标签为稳定格式、位于 `main`，并有同一提交的成功 `windows-ci.yml` push 运行。发布 job 定向到唯一带 `netboot-release` 标签的 Runner，避免恢复时路由到没有对应本地缓存的其他机器。
- GitHub-hosted 门禁还会检查发布标签自身包含发布脚本及依赖文件；过旧标签在派发到自托管 Runner 前明确失败。发布 job 从触发该工作流且通过 CI 的 `main` 提交加载发布工具，同时保留请求标签的应用源码和版本文件；这样可修复发布工具并安全重试旧标签，不移动标签或重建包。
- 发布 job 将固定 .NET SDK 安装到 Runner 用户的 `%LOCALAPPDATA%\NetBootDhcpTool\dotnet`，避免非管理员 Runner 写入 `C:\Program Files\dotnet` 失败，并在同一主机后续发布时复用 SDK。
- 发布脚本把归档和检查点写到 self-hosted Runner 工作目录外的持久缓存；重跑复用原文件，不重新构建。若本地缓存丢失但任一远端 Release 已存在，则失败并要求恢复原缓存，避免重建或产生重复附件。标签、提交或 SHA 不符时安全失败。
- GitHub 与 Gitee Release 仅在不存在时创建；新 GitHub Release 保持 draft、新 Gitee Release 保持 prerelease，直到归档、sidecar 与两端清单都完成读回验证。之后先发布 GitHub，再最后提升 Gitee；重跑可安全完成中断的最后一步。已有资产只有完整下载后哈希匹配才复用；不同内容的同名归档失败关闭，不删除或覆写 Release 资产。
- Gitee 附件上传返回 ID 后立即原子保存 ID 与下载地址。重跑优先通过官方单附件信息/下载 API 按 ID 校验；当前 API 不可用时，用该 ID 对应的已保存下载地址完整读回校验。附件列表只在上传结果不确定或缺失缓存时用于恢复。访问令牌通过 curl 标准输入传递，不写入持久状态目录。Release 元数据使用 JSON 请求；发布清单不得早于两端归档和 sidecar 的完整远端 SHA-256 校验。上传前检查本地文件名与远端附件名相同，避免清单被发布为错误名称。
- 保留 GitHub `main` 与稳定标签到 Gitee 的非强制快进同步。Gitee 上传结果不确定时先恢复附件身份；只有明确未被接受的请求允许有限重试。不跨境下载 GitHub 归档再传 Gitee。
- README、维护指南、待办索引和本发布流程统一指向当前接手入口、唯一状态来源及正式发布步骤；待完成的 Runner/远端验收明确标为阻塞。
