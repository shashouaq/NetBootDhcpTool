# T08 防火墙归属与异常恢复

类型：缺陷修复；风险：高；追溯：CODE-010、TEST-001、MAINT-002。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

临时 DHCP 防火墙规则从部分创建、正常停止到崩溃后恢复均有明确所有者，不能丢失清理责任或删除他人规则。

- 证据：[NetworkAdapterService.EnsureDhcpFirewallRulesAsync](../../src/NetBootDhcpTool.Network/NetworkAdapterService.cs) 使用固定显示名，脚本全部结束后才返回创建列表；部分创建命令没有终止式错误处理。
- [MainWindow](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 的 `_dhcpFirewallRules` 仅存内存；`RemoveDhcpFirewallRulesAsync` 的失败提示、停止成功提示和退出检查未统一。无规则的非空 lease 也需与真正未清理状态区分。
- 调用链确认：崩溃或部分创建失败可丢失归属；下次看到同名规则已存在也不能据此认领。尚未修改真实防火墙验证。

## 实现范围

允许调整防火墙创建/查询/删除服务、最小持久化归属模型、DHCP 启停与恢复中心的显示/清理，以及测试。可复用 T05 的执行器，不新建全局防火墙管理层。

边界：只清理本程序本次可证明拥有的规则；默认不删除既有同名规则。非目标：修改系统默认策略、开放更多端口或使用显示名/分组批量扫除规则。

## 业务规则与实现要求

- 创建前记录会话意图；每条规则用唯一实际标识记录程序路径、方向、端口、接口范围和拥有者，创建后回读并落盘。
- 第一条成功第二条失败、结果解析失败或落盘失败时尝试补偿；不确定归属的对象保持待核实，不能猜测删除。
- 已有同名规则先核对属性和归属；不满足当前需要时明确报错或另建明确拥有的新规则，不能静默扩大他人规则。
- 清理按精确标识及属性验证；规则不存在为幂等成功，外部修改时报告冲突并保留记录。
- 正常停止、启动失败和下一次启动使用同一恢复流程；失败项在 UI、日志、历史和退出结果中一致显示。空清理列表应表达“无需清理”。

## 验收标准

- [ ] 部分创建、取消、查询失败、保存失败、异常退出后重开，都能恢复本程序拥有的规则或保留明确未完成项。
- [ ] 既有同名/其他程序规则、属性被修改的规则不被误删；活动实例规则不被接管。
- [ ] 规则范围与 T07 的接口契约一致；停止后精确读回确认已删除，不再错误提示全部成功。
- [ ] 没有创建任何规则、重复清理及规则已被人工删除时结果正确，无虚假清理失败。

## 测试与回归要求

- 模拟执行器覆盖每条创建/删除后的故障点、记录写入失败和重启恢复；测试断言规则 ID、属性及保存顺序。
- 在获准的隔离测试环境创建唯一命名测试规则，验证读回、外部变化和清理；测试不能删除生产规则或按通用分组清理。
- 回归 DHCP 正常启停、启动失败、退出、恢复中心、多实例拒绝及接口范围；测试结束核对无测试规则残留。
