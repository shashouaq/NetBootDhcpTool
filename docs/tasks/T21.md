# T21 统一 PowerShell 进程执行边界

类型：可维护性与诊断；优先级：P1；风险：高；接手：Luna。状态见[待办索引](../TODO.md)。

## 目标与源码证据

收敛网络服务重复的进程生命周期逻辑，让超时、取消、失败和计时只有一份实现，供只读查询优化复用。

- 基线同 T20。[NetworkAdapterService.RunPowerShellOutputAsync](../../src/NetBootDhcpTool.Network/NetworkAdapterService.cs) 与 [StaticRouteService.RunPowerShellOutputAsync](../../src/NetBootDhcpTool.Network/StaticRouteService.cs) 各自负责 PowerShell 路径、编码、双流、30 秒超时、杀子进程及异常输出；路由执行壳记录耗时，网卡执行壳未统一记录。
- [PowerShellProcessOutput](../../src/NetBootDhcpTool.Network/PowerShellProcessOutput.cs) 已修复并发排空 stdout/stderr；[对应测试](../../src/NetBootDhcpTool.UnitTests/PowerShellProcessOutputTests.cs)已覆盖双路各 200,000 字符。不要将这项已有修复重新登记为成果。

## 实现范围与步骤

1. 在 Network 项目提取一个小型执行器，统一 Windows PowerShell 路径、隐藏进程、UTF-8、EncodedCommand、双流读取、退出码、30 秒默认时限和阶段耗时；业务脚本仍留在各服务。
2. 保留 `PowerShellScriptExecutor` 注入兼容层，现有网卡/路由/防火墙故障注入不需要改成真实系统调用。不要引入通用命令总线或 DI 容器。
3. 区分调用者取消、执行超时、非零退出和启动失败，保留原始异常因果及受控输出摘要。不要记录编码后的整段脚本、凭据或无限长 stdout/stderr。
4. 异常/取消时只终止本次创建的子进程树，等待回收并观察输出任务；回收等待本身有界，回收失败显式报告。超时不能释放业务工作流后让旧脚本继续写系统。
5. 确认原业务脚本、执行顺序、写前日志与独立补偿 token 未变；使用 T20 输出调用数和分段时间。该任务不以减少安全检查或子进程数量作为成果。

## 边界与非目标

- 不复用长期提权 PowerShell 会话，不改用 pwsh/Runspace/CIM 重写业务，不并行执行网络写入。
- 保留 [T03](T03.md) 工作流所有权、[T05](T05.md) 独立补偿、[T06](T06.md) 路由归属与 [T08](T08.md) 防火墙归属；公共执行器不自行重试写命令。
- 不修改 `build/process-safety.ps1` 的应用进程退出策略；结束本次命令子进程与强杀正在运行的用户应用是不同边界。

## 验收标准

- [x] 两个服务使用同一生产执行器；路径/超时/输出/回收逻辑不再复制，现有注入调用语义保留。
- [x] stdout/stderr 大输出、中文、空输出、非零退出、预取消、执行中取消及超时均有准确结果；没有未观察任务或测试子进程残留。
- [x] 取消与超时可区分，补偿使用独立 token，原始失败和补偿失败都能追溯。
- [x] 同一替身业务场景的命令顺序、目标身份、归属检查、提交/补偿次数与基线相同。
- [x] T20 报告包含成功、失败、调用方取消和超时各 5 次的真实 PowerShell 执行耗时，并核对耗时日志与子进程退出。
- [x] 在 UTF-8 输出修复后的最终 Release 产物上重跑管理员入口，隔离 Hyper-V 路由烟测和指定物理网卡取消/补偿仍通过。
