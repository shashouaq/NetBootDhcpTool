# T24 租约状态与连通性探测解耦

类型：运行效率与状态一致性；优先级：P1；风险：中；接手：Luna。状态见[待办索引](../TODO.md)。

## 目标与源码证据

让租约状态及时显示，慢设备不阻塞其他租约，旧探测不能覆盖终态或新持有者的状态。

- 基线同 T20。[MainWindow.UpdateLeaseAsync](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 持有 `_leaseUpdateGate` 时等待 Ping 和 HTTP/HTTPS；后续租约事件因此排队。
- `RefreshLeasePingAsync` 每两秒触发，但一轮内对全部活跃租约逐条等待；`ProbeLeaseConnectivityAsync` 只在 await 前检查当前会话/有效期，返回后直接更新行对象。
- 当前周期探测有防重入标志，`DhcpLease` 已实现属性通知；[T09](T09.md)已分离协议状态和 Ping。新任务只解决调度与异步结果有效性，不重新实现 DHCP 协议。

## 实现范围与步骤

1. 提取小型租约探测协调器；UI 上先按原有顺序应用 Assigned/续租/Released/Declined/Expired 事件，再安排探测。状态合并的串行区不得跨网络 await，也不得等待日志/历史批量刷新。
2. 探测身份使用 `SessionId + ClientKey + IP + 绑定代次`，以不可变请求值启动；应用结果前重新检查当前会话、活跃状态、未过期和完整身份。同 IP 换 MAC/ClientKey、重启、释放和续租更新都能使旧结果失效。
3. 单协调器最多 8 个在途租约探测，待执行队列上限 64；同一绑定的重复周期请求合并为最新一项。队列满时由后续轮次补探测，不能丢失协议状态事件或创建无界等待任务；公平遍历避免末尾租约一直得不到探测。
4. 事件触发的 Ping/Web 与周期 Ping 共享去重责任，避免同一绑定同时重复探测；周期刷新不擅自变成每两秒扫描全部 HTTP 端口。网络探测复用 T23 传输及总并发门禁。
5. DHCP 停止、意外停止、会话更换和窗口关闭时取消该会话探测并等待受控退出；忽略全部迟到结果。网络系统补偿继续使用 T03 的独立 token，不被探测取消影响。

## 边界与非目标

- 不改变 `DhcpLeaseManager`、DORA/续租/释放协议决策及 ACK 前持久化；不把恢复日志或租约协议事件改成可丢弃队列。
- 保留最后上线时间仅在不可达变可达时更新、终态清空当前 Ping/HTTP/HTTPS、历史租约不探测的规则。
- 不新增后台常驻扫描，不删除用户看到的租约历史，不通过修改租期或探测范围提升指标。

## 验收标准

- [x] 用受控永不立即完成的探测挂起一台设备，其他租约状态以及该设备 Released/Expired 状态仍可立即提交到 UI，无需等待超时。
- [x] 探测在释放、过期、停服、重启或 IP 被新客户端复用后返回成功，旧结果一律不能复活旧行或写到新行。
- [x] 128 条合成租约下最大在途为 8、队列不超过 64；重复事件不重复排队，后续轮次覆盖暂缓的活跃租约。
- [x] 关闭/停服后无存活探测任务、无 Dispatcher 迟到写入；取消/失败有可追溯结果。
- [x] T20 报告给出整轮探测耗时和任务峰值；UI smoke 另外测量了挂起探测期间 Released 事件到达 UI 的延迟。
