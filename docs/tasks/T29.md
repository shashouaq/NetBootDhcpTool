# T29 便携包目录与 Full/OTA 安全自动更新

类型：用户功能与发布链路；优先级：P1；风险：高。状态见[待办索引](../TODO.md)。

## 目标与当前现状

发布包增加一个固定名称 `NetBootDhcpTool/` 顶层目录，用户解压后能直接移动该目录。程序内更新支持完整 Full 包和基于精确旧版本的 OTA 增量包；下载并校验完成后，工具栏显示“重启升级”。独立更新进程在主程序正常关闭后应用更新、验证文件并启动新版本，任何应用失败都可恢复旧版本。

- 实施前，`build/publish.ps1` 从版本化发布目录打包，没有固定名称的产品根目录；只生成 `.7z` 和旧格式 `latest.json`。
- 实施前，`VersionUpdateService` 与 `UpdateController` 只发现/下载 `.7z`，SHA-256 通过后保存到 Downloads，不执行安装。
- 实施前，`MainWindow` 在工具栏提供新版本链接和下载取消；其 `OnClosing` 已有异步恢复/清理流程，更新不能绕过或强制结束该流程。
- T14、T18、T19、T28 已覆盖下载落盘、多源分发、正式发布恢复和更新职责拆分。本任务只扩展其协议/发布资产并复用现有能力；不重新实现旧协议，也不改变既有 Gitee/GitHub 源选择规则。

## 实现范围

1. **便携布局与本地发布物**
   - `.7z` 文件名仍为 `NetBootDhcpTool-v<version>.7z`，归档根新增 `NetBootDhcpTool/`；应用、更新器、资源和用户说明放在该目录内。
   - 每版另外生成 `NetBootDhcpTool-full-v<version>.zip` 和 `NetBootDhcpTool-ota-v<base>-to-v<version>.zip`。Full 包提供完整受管文件集；OTA 仅含变更/新增文件、删除清单及精确 base version/base file hashes。
   - 生成产品安装清单，描述产品 ID、版本、应用入口、受管文件相对路径及目标 SHA-256。安装清单不把 `%LOCALAPPDATA%\NetBootDhcpTool` 纳入应用目录。

2. **向后兼容的签名更新清单**
   - 保留 `version/archiveName/archiveSha256/downloadUrl/downloadMirrors/releasePageUrl` 既有字段和 `.7z` 资产，供尚无自动更新器的客户端继续手动下载。
   - 扩展清单提供 Full/OTA 包元数据、各镜像下载 URL、大小/哈希、目标版本和 OTA 基线信息。新客户端只接受严格白名单中的 HTTPS 项目 Release URL；只有实际清单的版本、归档名和 SHA-256 与选中的正式版本一致的镜像才参与测速和下载，Gitee-only 环境仍可使用有效 Gitee 清单。
   - 对最终双源清单的确切字节生成 detached RSA-PSS/SHA-256 签名；客户端使用编译进程序的公钥校验签名后才信任新包元数据。发布脚本不得记录私钥内容；正式发布前必须在自托管发布环境配置与客户端固定公钥匹配的私钥。缺少密钥时发布明确失败或只生成不可自动安装的开发包，不得悄悄发布可执行的未签名更新。
- Full 始终可用；只有 OTA base version 与本机安装清单版本/摘要一致时才先下载 OTA。更新器继续验证每一个基线文件；若已安装文件漂移，客户端改下 Full 修复包。按归档体积避免发布比 Full 更大的 OTA。

3. **独立更新器与事务应用**
   - 将更新器随便携目录交付。主程序启动更新时，先将其复制到 `%LOCALAPPDATA%\NetBootDhcpTool\Updater` 的稳定位置再执行，避免目标目录内更新器自锁。
   - 下载到 `%LOCALAPPDATA%\NetBootDhcpTool\updates\staging`，完整校验签名、包哈希、版本/基线、条目数量/总长度和所有目标路径后才进入可应用状态。拒绝绝对路径、`..` 穿越、重复路径、链接和越过目标根目录的 reparse point。
   - 以应用实际路径为目标（不使用进程当前工作目录）；预检写权限和磁盘空间。只修改清单拥有的文件，不删除未知文件、用户文件或用户数据。
   - 更新器确认目标进程身份后等待其正常退出及单实例锁释放；超时/拒绝关闭时不动安装目录。备份即将变更的受管文件，逐项以同目录暂存和原子替换；失败时按事务日志逆序恢复。启动新版并等待带事务 nonce 的启动健康回报，失败则正常关闭新版并恢复旧文件后启动旧版。保留最近一次可用备份，清理仅删除本事务自有暂存物。

4. **更新 UI**
   - 保留更新内容确认、多源测速、下载进度、取消、低速提示及失败重试。
   - 下载/全部校验通过后工具栏更新为双语“重启升级”；点击后再次清楚说明程序将正常关闭并重启。只有更新器成功受理事务后才触发现有正常退出清理。
   - 界面区分准备中、等待退出、应用、启动验证、回滚及完成/失败；没有签名有效的自动更新包时仍提供既有手动 `.7z` 下载，但不显示“重启升级”。
   - 发布说明同时提供中英文；新客户端按用户配置的 `Language`（`zh-CN`/`en-US`/`auto`）选择对应内容，`auto` 跟随系统 UI 语言。旧客户端仍收到兼容的双语摘要。

5. **正式发布资产**
   - 扩展本地包验证、`ClientManifestCheck` 和幂等发布流程，确保 `.7z`、Full、所有声明的 OTA、哈希 sidecar、最终双源清单及签名在 GitHub/Gitee 同名发布并完成匿名读回校验后才提升稳定 Release。
   - 同标签重试必须复用缓存中的同一组包和签名；不得重建或覆盖已有的不同字节资产。未获得用户明确发布授权时只运行本地构建/测试，不推送、打标签或发布。

## 边界与非目标

- 不改变 DHCP、网卡、静态路由及现有恢复业务；更新退出只调用主窗口既有的异步关闭/恢复链路。
- 不改变 `%LOCALAPPDATA%` 中收藏、凭据、恢复日志、网络历史及设置的位置或内容，不覆盖用户数据。
- 不执行未签名下载、不降级版本、不应用不匹配基线的 OTA、不强制终止应用、不在失败时静默丢弃旧版本。
- OTA 本任务定义为按文件的版本差异包；不实现二进制差分算法。单文件自包含 EXE 在多数应用版本更新时会变化，OTA 无显著体积收益时选择 Full。
- 本任务不执行 GitHub/Gitee 发布，也不代表首次自动更新启动版本已对外发布。既有客户端没有更新器，启用后第一版需要用户手动解压一次；该版之后才可自动重启更新。
