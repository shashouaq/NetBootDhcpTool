# T25 批量刷新扫描结果与操作历史

类型：运行效率与 UI 响应；优先级：P1；风险：中；接手：Luna。状态见[待办索引](../TODO.md)。

## 目标与源码证据

减少大量命中时的 UI 通知、列表重建和磁盘同步写入，保留真实结果和明确的保存边界。

- 基线同 T20。[MainWindow.ApplyAndScanAsync](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 为每个进度回调更新 UI，每次命中调用 `AddOperationHistory`。
- `AddOperationHistory` 每次保存完整最近 500 条历史，再由 `RefreshOperationHistoryView` 清空/重建可见集合；[JsonStore.Save](../../src/NetBootDhcpTool.Core/JsonStore.cs) 会读取并验证主/备份、写入并 flush 临时文件、原子替换。成本不只是一次列表插入。
- 现有 4096 地址上限、结果虚拟化和历史 500 条上限继续保留；不把已有保护作为新功能。

## 实现范围与步骤

1. 给每轮扫描分配代次。后台进度进入有界批处理器，最多每 100 ms 调度一次 UI；完成/取消强制消费已接受结果。进度值保持单调，结果不得因节流丢失；旧代次回调不能进入新扫描。
2. 队列容量不得超过本轮合法目标数（最多 4096）；单目标重试只保留最新进度。每次 UI 消费最多 128 条，剩余让出 Dispatcher 后继续；同批内统一刷新进度、数量、空状态和过滤视图。
3. 提取独立的操作历史存储/呈现责任。只对高频扫描命中历史合并保存：每 500 ms 或积累 128 条提交一次，以先到为准；保存不可变快照，通过单写入者串行使用现有 JsonStore，禁止每条启动一个 Task.Run。
4. 历史内存仍保留最近 500 条；完成/取消/关闭/导出前等待已接受历史提交，最后写入操作终态。清空历史需与待保存批次串行，使用代次避免旧批次将清空内容写回来。恢复/回滚等低频关键操作历史沿用明确提交点。
5. 可见历史改为集合视图过滤或最小增量更新，避免每个命中 Clear/Add 500 次；保留排序、筛选、选中项及“复制选中或可见行”语义。不同时重构收藏/方案编辑。
6. 持久化失败保持文件原件，显式显示未保存状态并保留可重试快照；读失败不初始化成可写空历史。导出/清空/关闭不得报告保存成功而后台仍失败。

## 边界与非目标

- 批量窗口只适用于展示进度和普通扫描命中历史；DHCP ACK 前租约落盘、网卡快照、路由意图/逐条清理、防火墙恢复记录、收藏凭据均继续原来的立即提交规则。
- 正常退出必须排空；异常强制结束最多丢失尚未提交的普通扫描历史批次，此语义写入维护说明，不能宣称崩溃零丢失。不得改变系统恢复承诺。
- 不删除扫描结果来减少行数，不提高扫描范围，不关闭 DataGrid 虚拟化，不更换 JsonStore 的全局损坏保护。

## 验收标准

- [x] 4096 个合成命中结果全部且仅出现一次，进度不倒退；取消保留已接受结果，新扫描/关闭后不接受旧回调。
- [x] 在 4096 命中夹具中，按 128 条/批提交并最终排空，历史保存次数不超过 33，最终内容等于原规则下最近 500 条。
- [x] 多次保存不会重叠或用旧快照覆盖新状态；保存失败、清空覆盖待保存批次及关闭均有确定结果。
- [x] 非管理员 UI 洪峰下，已测取消、筛选、选中/可见行复制和最后一批消费；性能报告记录保存次数，UI smoke 输出分批消费数据。
- [x] 恢复日志和收藏主/备份的损坏保护回归不变；未保存错误会保留内存快照并提示，不被“已完成”反馈掩盖。
