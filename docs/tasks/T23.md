# T23 复用探测连接并缩短单目标等待

类型：运行效率；优先级：P1；风险：中；接手：Luna。状态见[待办索引](../TODO.md)。

## 目标与源码证据

减少每台在线设备的串行等待和传输对象创建，让网段扫描、单目标扫描、租约探测复用同一探测实现。

- 基线同 T20。[HttpProbeService.ProbeAsync](../../src/NetBootDhcpTool.Network/HttpProbeService.cs) 顺序等待 HTTP、HTTPS；`ProbeOneAsync` 每次创建并释放 handler/HttpClient。
- [NetworkScanTargetProbe.ProbeAsync](../../src/NetBootDhcpTool.Network/PingScanner.cs) 在 Ping 成功后先等待 DNS，再等待 Web 探测；[MainWindow.ProbeTargetUntilOnlineAsync](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 有另一份相近逻辑。
- PingScanner 已有惰性枚举、4096 目标范围保护、最大 64 目标并发及阶段取消；这是 [T11](T11.md) 已完成能力，不重做。

## 实现范围与步骤

1. HttpProbeService 使用可注入、由明确所有者管理的长期 HttpClient/handler；同一服务生命周期内复用传输，应用关闭时在所有探测结束后释放。不得借用或释放更新服务的独立客户端。
2. 每个请求使用独立的 linked CTS 控制设置中的超时和调用者取消，不在并发请求间修改共享 `HttpClient.Timeout`。HTTP/HTTPS 在受限条件下同时开始，仍返回两个独立结果并观察所有任务。
3. 增加应用探测服务级请求门禁，总在途 HTTP 请求不超过 64（包括扫描和租约调用）；等待门禁可取消。复用传输时不能跨设备共享 Cookie/凭据，保留系统 TLS 验证、HEAD/响应头即结束的行为与响应释放。
4. Ping 成功后 DNS 和 Web 探测并行，DNS 仍有 1.5 秒独立上限；DNS 无结果不阻止 Web 结果。完整结果仍由一个统一方法组装，供网段扫描和单目标成功后的信息补全调用；单目标离线时继续按原规则重试。
5. 复用现有 `IScanTargetProbe`、Ping/DNS/HTTP 替身接口。以信号控制证明两个协议及 DNS/Web 确实重叠，不只用脆弱的墙钟断言。用 T20 记录传输创建次数、最大并发与慢目标总时长。

## 边界与非目标

- 不提高 4096 地址及 64 目标并发上限，不对 Ping 不通的全网段额外做端口扫描；不接受任意 HTTPS 证书。
- 不改变任何 HTTP 状态响应均可说明端口可达的现有语义，不下载响应正文，不引入外部探测服务器。
- 不添加长期主机名/在线状态缓存；新扫描必须反映本轮结果。T24 负责租约调度和迟到结果，T25 负责 UI 批量更新，本任务只处理探测传输和单目标流程。

## 验收标准

- [x] 多目标重复探测的传输创建次数不再与 HTTP 请求数线性增长；注入客户端的所有权、关闭/释放可验证。
- [x] 慢 DNS、慢 HTTP、慢 HTTPS 的等待可以重叠；达到并发上限后不会继续增加在途请求，等待和执行阶段均可取消。
- [x] 用户取消能停止两种协议和 DNS，全部任务被观察；超时只影响相应探测，下一次请求不继承其 token/超时状态。
- [x] 单目标持续等待、普通 `/24`、4096 边界、非法目标和收藏应用保留原语义；取消后无后台请求持续增长。
- [x] 有 T20 前后对比，说明传输创建/并发上界和实际样本，不能把局部等待减少直接称为整体扫描提升同等比例。
