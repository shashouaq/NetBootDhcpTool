# T07 DHCP 收发限定所选接口

类型：网络安全；风险：高；追溯：CODE-002、TEST-002。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

DHCP 报文只能由用户确认的隔离网卡接收和发送，UI 选中接口必须成为服务层可验证的约束。

- 证据：[DhcpServer.StartAsync](../../src/NetBootDhcpTool.Dhcp/DhcpServer.cs) 绑定 `IPAddress.Any`，`LoopAsync` 不校验入站接口并向有限广播/子网广播发送；[DhcpServerSettings](../../src/NetBootDhcpTool.Dhcp/DhcpModels.cs) 未携带接口身份。
- [MainWindow.StartDhcp_Click](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 只将 ServerIp 等配置传给服务；[防火墙创建](../../src/NetBootDhcpTool.Network/NetworkAdapterService.cs) 按程序/端口放行，未限定接口。
- 代码缺少范围限制已确认；真实多网卡泄漏/响应情况尚未抓包，不得写成已发生办公网干扰。

## 实现范围

允许修改 DHCP 服务启动契约、接口身份解析、UDP 收发与停止条件、主窗口参数传递和针对性测试；防火墙接口范围与 T08 对接。

边界：保留隔离网络确认、Wi-Fi/非安全网卡限制、正常广播客户端兼容、测试回环注入能力。非目标：开放办公网 DHCP、DHCP Relay、IPv6 DHCP、跨网段服务或替代系统路由策略。

## 业务规则与实现要求

- 服务启动前验证稳定网卡身份、有效接口索引、配置地址和连通状态；运行中不能随 UI 选择改变目标。
- 接收必须识别报文进入的接口并拒绝非目标接口；发送必须显式约束出口。不能仅将 Any 换成 ServerIp 就认定广播接收安全且兼容。
- 保留从 `0.0.0.0` 发起的普通客户端 Discover/Request 能力；选择适合 Windows 的套接字/接口信息机制，用测试证明收发范围。
- 接口消失、身份变化或必要地址丢失时明确停止并保留原恢复责任，不回退到默认路由/当前选中接口。
- 防火墙按最终接口范围创建；关闭服务释放端口及套接字，不能以 ReuseAddress 掩盖其他服务占用。

## 验收标准

- [x] 双隔离接口 A/B：目标以太网 ifIndex 13 上真实独立 DHCP 客户端完成 Offer/Ack，非目标 B(44) 的 Discover 零响应；回复接口受 `IP_UNICAST_IF` 固定为 13。
- [x] 默认路由位于办公接口 ifIndex 11 时，目标接口 13 的标准 DHCP 会话仍成功；有限广播和子网广播均记录为接口 13 出口。
- [x] 目标身份/地址变化由契约测试 fail-closed；目标地址 UDP 67 端口冲突实测停止且不回退到另一接口。
- [x] 停止后标准端口可独占重绑；真实客户端、隔离 UDP DORA 和回环协议回归通过。

## 测试与回归要求

- 自动化测试覆盖启动契约、接口筛选、发送目标和目标失效；保留现有回环协议烟测。
- 必须在两个隔离虚拟或专用测试接口上抓包/计数验证入站与出站，验证时不得连接办公或生产广播域。记录接口身份、源/目的地址、报文类型及非目标响应数为零。
- 回归 Windows 多网卡、不同跃点、目标网卡断开、端口占用、T01 恢复目标、T03 互斥；不能用单回环测试替代多接口验收。
