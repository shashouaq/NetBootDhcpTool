# T16 操作阶段进度与分段计时

类型：用户体验及运行诊断；风险：低。状态见 [待办索引](../TODO.md)。

## 目标与现状

让用户在启动、网络操作和退出恢复期间看到正在执行的阶段、阶段计数和已耗时；同时留下可比较的分段计时，为后续性能优化提供数据。此任务的交付是进度可见和耗时可观测，不宣称操作本身已经变快。

主窗口已有扫描专用进度、耗时和剩余时间，但启动网卡/路由读取、多个网络变更步骤及关闭清理此前没有统一的阶段计时。应用启动日志也没有覆盖完整启动节点。

## 实现范围

- 启动时记录单实例锁定、数据目录初始化、主窗口构建、窗口显示、首帧呈现、网卡与路由读取，以及残留路由恢复的阶段耗时。主窗口在初始化时显示提示，并在可计量的网卡/路由读取期间显示进度与耗时。
- 主窗口的 DHCP 启停、网卡刷新/重启、MAC 变更、静态路由预览/应用、手动恢复和回滚显示当前阶段。已具备扫描专用进度/ETA 的扫描流程继续使用该界面。
- 正常关闭时展示保存恢复状态、停止 DHCP 和清理防火墙/路由/DHCP 网卡/MAC 的阶段；用户在操作中请求关闭时，显示取消与等待恢复的阶段。
- 阶段数量已知时显示计数进度；数量未知时保留活动指示和分段/总耗时。日志按操作关联标识记录阶段名和各段耗时，不按秒写日志。
- Windows 会话结束事件记录诊断信息，窗口关闭流程继续执行已有恢复清理。进程被强制结束后界面已不存在，无法显示后续进度；下次启动继续依赖既有的持久化恢复记录和恢复中心处理未完成状态。

## 业务边界与非目标

- 不调整 DHCP、网卡、MAC、路由、防火墙的修改顺序、确认条件、所有权校验、取消补偿、超时或恢复规则。
- 不因启动、关机或关闭窗口而强制结束任何其他进程；强制终止后的故障恢复仍由现有恢复日志负责。
- 不增加计时阈值或宣称性能改善。分段数据用于发现以后应优化的具体慢阶段。
- 不把启动检查、扫描或退出恢复改为可以忽略失败的后台工作。

## 验收标准

- [x] 启动日志包含应用初始化及主窗口首次呈现的分段耗时；网卡/路由发现显示阶段进度。
- [x] 长操作能显示当前阶段、阶段计数（适用时）、阶段耗时和总耗时；日志包含可关联的阶段计时。
- [x] 正常退出清理按既有次序显示阶段；取消活动操作并等待补偿时显示独立的等待阶段。
- [x] UI 回归验证进度阶段推进、计数和耗时显示；全解决方案构建、现有单元/控制台/UI 烟测及维护检查通过。
- [x] 已说明进程强制结束后的显示边界和现有恢复机制；未更改网络业务行为。

## 验证

- Release 全解决方案构建，输出使用隔离 artifacts 目录，不覆盖当前预览。
- MSTest、控制台烟测和非管理员 WPF UI 烟测。UI 烟测验证阶段计数推进、累计耗时及关闭时等待当前操作释放。
- 按维护指南启动源码 Release 预览并核对启动分段日志；RunAs 不继承调用进程的临时数据目录环境变量，预览因此使用本机正常 LocalAppData。启动只读网卡/路由状态，没有执行 DHCP、网卡或路由写操作。
- 维护检查和 `git diff --check`；检查本任务新增的 Markdown 本地链接。
- 不执行真实网卡、MAC、DHCP 或系统路由修改；这些不属于进度 UI 的验收条件。
