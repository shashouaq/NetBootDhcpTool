## 实现范围与步骤

1. 在现有测试项目及 `build/` 内增加 `build/measure-performance.ps1` 入口；复用 `IScanTargetProbe`、`PowerShellScriptExecutor` 和唯一临时目录，不新建独立测试框架。默认仅运行替身、临时文件和隔离 UI 场景，不执行网卡写入或真实网段扫描。
2. 建立固定夹具：扫描 254/4096 个目标（可控命中率、DNS/HTTP 慢响应）；租约 1/32/128 条及续租洪峰；历史 500 条；日志 10,000 条；100 次网络变化通知。输入使用合成数据，不读取用户收藏或凭据。
3. 对各场景记录总耗时、首条结果时间、取消排空时间、CPU 时间、托管分配/峰值工作集、PowerShell 调用次数、历史保存次数、UI 刷新次数及最大待处理数。只实现该场景有意义的指标，注明采样方法与缺失项；不能拿当前线程分配量冒充异步全进程分配量。
4. 导出可对比的 JSON/CSV，包含提交、版本、SDK、OS、配置、夹具、预热次数和每次原始样本。同一受控场景至少运行 5 次，报告中位数和最大值；只有达到 20 次才报告 P95。原始产物写到指定临时/忽略目录，摘要进入变更日志。
5. 真实启动/刷新可另做只读同机采样；DHCP 启停、MAC、网卡写入等只有在指定隔离环境下按原任务矩阵测量。把进程启动、Windows 查询、协议探测、持久化、UI 消费等阶段分开，避免把 T17 历史约 45 秒的 DHCP 启动记录当成本版本实测。

## 边界与非目标

- 不升级 .NET/MSTest、安装全局服务、发真实 DHCP 广播或修改生产/办公网络。
- 不设未经测量的“整体提速 50%”结论；后续任务首先以进程数、批次数、并发上界等确定性指标验收，再报告时间差异。
- 不把有噪声的墙钟阈值直接变成 CI 门禁。CI 运行确定性行为断言；实机性能对比单独记录环境和波动。
- 本任务只建立测量能力，不提前实现 T21～T28 的优化。

## 实施与基线记录 / 2026-09-26

- `build/measure-performance.ps1` 通过 MSTest `Performance` 分类调用真实产品 `PingScanner.ScanTargetsAsync` 和 `FileLogger`，每个夹具运行 5 次。报告含提交/dirty 状态、应用版本、SDK/runtime、操作系统、处理器、机器名、每次耗时/CPU/分配/托管堆及结果数。原始 JSON 位于忽略目录，不会提交。
- Release build 0 警告/错误；原有 MSTest 150/150、控制台 `OK`、标准用户 UI `UI_SMOKE_OK`、发布辅助测试与维护检查通过。测量命令连续运行两次并生成 JSON：`artifacts/performance/performance-b586c6f-20260926-235309.json` 和 `artifacts/performance/performance-b586c6f-20260926-235433.json`。
- 同机两次运行的基线中位数：4096 个合成目标并发峰值 64，1,007.6/1,007.8 ms；254 个目标为 59.1/60.3 ms；每轮写入 10,000 条临时会话日志为 5,007.0/4,914.9 ms。各场景 5 个原始样本，结果会随系统负载变化。
- 扫描实测执行现有 `PingScanner` 配合 1 ms 可控探针，未运行真实 ICMP、DNS、HTTP、网卡或 UI；日志实测 `FileLogger.Info` 写入临时目录，并核对每轮 10,000 行。
- 本报告后续对比：同一主机、SDK/runtime 和合成夹具下，会话日志 10,000 行中位数从 `4,914.9 ms` 降至 `77.1 ms`；T23 HTTP 64 目标 fixture 的传输创建从 128 次降为 1 次。4096 个可控扫描目标中位数 `1,004.8 ms`，与基线 `1,007.8 ms` 接近，不能表述为整体扫描提速。
- T24 合成调度 128 个绑定、最多 8 个并发和 64 个待执行，队列满的 56 个目标由下一轮补测；慢探测期间另一租约状态事件在 UI smoke 中约 `4.6 ms` 到达；T25 4096 个命中每 128 条保存一次，共 32 次 `JsonStore` 提交并读回最近 500 条；T27 101 个事件在活动读取期间合并成两次读取。最终报告中，显示字段未变化比较 100,000 次的中位数为 `0.36 ms`，分配量中位数为 `63,544` 字节；全量列表选中行与稳定 ID/index 定向读取中位数分别为 `19.2 ms`、`18.8 ms`。这些比较器和只读调用计时不代表三秒轮询、Windows 枚举或 WPF UI 的总开销，也未观察到明确墙钟优势。
- T22 旧四次生产只读查询与新单快照的五样本中位数分别为 `4,669.7 ms`、`1,342.9 ms`；PowerShell 进程调用从 4 次降到 1 次，`Get-NetIPInterface` 从 3 次降到 1 次，另两类查询各 1 次。墙钟值依赖当前 Windows 主机负载，不作为 CI 阈值。
- T21 的真实 PowerShell 执行器 fixture 各运行 5 次安全脚本：成功、预期非零失败、调用方取消、执行超时的中位数分别为 `307.5 ms`、`383.6 ms`、`45.2 ms`、`272.5 ms`。每个样本均核对预期结果、包含 `elapsedMs` 的对应日志以及子进程退出；脚本仅输出、抛出合成错误或短暂 `Start-Sleep`，不做网络写入。
