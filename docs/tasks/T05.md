# T05 网卡修改补偿与原状态恢复

类型：缺陷修复；风险：高；追溯：CODE-004、CODE-005、TEST-001、MAINT-001、MAINT-002。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

系统操作部分成功后，异常、取消或超时仍能恢复正确原状态；不能将“方法未返回”当作“没有修改”，也不能用不完整读回宣称恢复成功。

- 证据：[NetworkAdapterService](../../src/NetBootDhcpTool.Network/NetworkAdapterService.cs) 的 `ApplyStaticIPv4Async` 先关闭 DHCP、移除地址/默认路由，再创建地址；`RestartAdapterAsync` 的 Disable 与 Enable 之间可被取消。
- [MainWindow](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 的 DHCP 启动在整个应用调用返回后才设 `adapterConfigured`；手动配置的应用错误也未完整进入校验失败补偿。MAC 调用须同步检查“实际改变但方法失败”的记录保留。
- `CaptureIPv4ConfigAsync` 未记录 DNS 自动/手动来源；`RestoreIPv4ConfigAsync` 将非空 DNS 恢复成静态值，空地址快照可能被恢复为 DHCP。`VerifyRestoredAdapterConfigAsync` 只验证 DHCP 状态和地址。
- 上述均为调用链确认，尚未执行真实 Windows 配置恢复矩阵。

## 实现范围

允许修改网卡执行器、IPv4/MAC/管理状态快照的必要字段与兼容、主窗口及恢复中心的修改/补偿编排和测试。可提取小型可替换 PowerShell 执行边界，统一结果、并行读取标准输出/错误、取消和超时语义。

边界：只操作经稳定身份确认的目标；DHCP/手动配置仍不修改 WLAN、不写本机网关/DNS、不改 WcmSvc，仍保留高跃点策略。非目标：新增网卡类型授权、企业网络管理或全窗口架构重写。

## 业务规则与实现要求

- 首次系统写入前成功保存原状态和操作意图；保存失败立即停止。逐步记录已尝试/已确认修改，不依赖最终方法返回布尔值决定补偿。
- 取消停止后续业务步骤，但补偿使用独立有界令牌；补偿失败保留恢复信息并说明剩余风险，不显示“已回滚”。
- 捕获并恢复本工具会影响的地址、DHCP 模式、DNS 配置来源、默认路由、自动/手动跃点；重启/MAC 额外处理原管理状态和原 MAC。
- 正常重启成功时保留既有“最终启用”行为；失败或取消的补偿才恢复操作前管理状态，不能为恢复快照而把成功重启变成再次禁用。
- 旧快照缺少新字段时采用明确兼容策略，不猜测 DNS 来源；无法完整恢复须显示限制并保留记录，不能伪造验证成功。
- 静态空配置保持静态；自动 DNS 使用自动获取，手动 DNS 保留原值；读回校验同时覆盖地址、DNS 来源/值、路由和跃点。
- 目标消失或外部修改冲突时不写入其他接口、不强制覆盖；恢复记录在全部必要验证成功后才清除。

## 验收标准

- [x] 在 DHCP/手动配置的各地址写入边界、修改 MAC 后分别注入失败/取消，能恢复或明确留下可重试记录。
- [x] 取消发生在 Disable/Enable 之间不会无提示留下禁用网卡；保留原本禁用的状态语义。
- [x] DHCP 自动 DNS、手动 DNS、静态多地址/多默认路由、自动/手动跃点和静态空配置均按原语义恢复。
- [x] 读回不一致显示失败，不能只凭退出码/地址相同清空记录；历史快照不会被无声升级成错误配置。

## 测试与回归要求

- 故障注入覆盖每个修改后的边界、令牌取消及补偿再次失败；测试必须断言写入顺序、目标、保存时点和最终状态，而非只捕获异常。
- 仅在专用隔离接口/可控制测试驱动条件下执行恢复矩阵；MAC/禁用测试不得使用承载当前办公/远程连接的接口。缺少条件保留待验收。
- 回归 T01 的停止/退出身份、T03 的操作互斥、T04 的保存失败，以及恢复中心、手动扫描、DHCP、MAC、重启和历史记录。

## 当前执行进展（2026-09-23）

DHCP/手动 IPv4 操作已共用有界补偿：失败或取消时使用独立 30 秒令牌恢复完整原快照，再捕获读回比较；补偿失败抛出聚合错误并保留恢复信息。MSTest 故障注入覆盖 DHCP 禁用、移除地址/路由、创建地址、设置跃点/DNS 六阶段及补偿失败；重启覆盖禁用后错误、Disable/Enable 间取消、原本禁用网卡及成功后最终启用。MAC 变更也已接入独立有界补偿协调器：无论退出恢复选项如何，系统写入前先落盘短期恢复意图；写后异常/取消恢复预操作 MAC 并校验，补偿失败保留并读回可持久化的恢复记录，成功后恢复用户选择的退出策略。MSTest 已覆盖写入后抛错、写入后取消、补偿失败和恢复记录序列化。隔离矩阵首轮读回到本机真实边界后，任务进入待验收。
