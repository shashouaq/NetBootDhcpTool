# T02 同数据目录单实例与恢复归属

类型：安全边界；风险：高；追溯：CODE-007、TEST-001、TEST-003。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

同一数据目录只能有一个写入和恢复责任主体，第二实例不能覆盖数据或接管活跃实例的网络恢复记录。

- 证据：[App.OnStartup](../../src/NetBootDhcpTool.App/App.xaml.cs) 在互斥保护前执行 Defaults；[JsonStore.Save](../../src/NetBootDhcpTool.Core/JsonStore.cs) 只有进程内锁，使用固定 `.tmp`、`.bak`。
- [MainWindow.RecoverStaleRoutesAsync](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 根据会话文件存在判断“残留”，未验证拥有者存活；确认后可能清理另一活跃实例的资源。
- 调用链已确认；未对真实共享数据执行多实例破坏性实验。

## 实现范围

允许修改 App 启动/退出、[AppPaths](../../src/NetBootDhcpTool.Core/AppPaths.cs) 的规范化数据目录身份、跨进程互斥及必要会话所有权元数据、相关测试。持久化读取失败语义由 T04 负责。

边界：用户数据目录与旧文件兼容不变，第二实例不得先执行默认化或迁移写入再退出。非目标：支持多个实例同时编辑同一配置、自动终止其他实例、跨用户共享网络管理。

## 业务规则与实现要求

- 首选“同一规范化数据目录单实例”；在 Defaults、迁移、恢复记录读取/接管和网络副作用之前取得所有权。
- 明确目录大小写、相对/绝对路径及别名处理，避免一个目录生成不同锁；锁生命周期覆盖整个退出清理。
- 第二实例只提示已有实例或激活窗口，不保存任何共享数据，不清理已有恢复记录，不强杀首实例。
- 正常退出释放所有权；异常退出后允许新实例接管，但遗留记录仍需稳定身份和资源归属校验。
- 不同测试目录可以隔离运行，但不能据此宣称允许同时修改同一系统网卡；全局网络资源仍遵守归属规则。

## 验收标准

- [x] 同目录并发启动时只有一个实例执行默认化、迁移、写入和恢复；第二实例行为可见且无副作用。
- [x] 不同 exe 路径指向同一目录仍互斥；目录大小写或等价路径不绕过保护。
- [x] 首实例清理未结束时第二实例不能接管；异常退出后可安全重开且不丢恢复记录。
- [x] 活跃实例的路由不会被显示为可接管的残留，收藏与方案无后写覆盖和临时文件竞争。

## 测试与回归要求

- 在独立临时目录创建两个真实测试进程验证竞争、退出与崩溃；断言文件哈希和副作用计数，不能只做同进程 Mutex 单测。
- 补目录规范化和锁释放异常测试；所有进程、日志和数据由测试自己创建并清理。
- 回归首次启动、历史目录迁移、默认收藏、恢复中心、预览启动，以及非管理员 UI 烟测；不得用真实用户数据模拟冲突。
