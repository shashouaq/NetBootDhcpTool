# T28 提取更新功能控制器与类型化测试入口

类型：代码可维护性；优先级：P2；风险：中；接手：Luna。状态见[待办索引](../TODO.md)。

## 目标与源码证据

以更新功能为有限切口减少主窗口职责，形成下一次维护可复用的分层方式；本任务不承诺提速。

- 审查基线同 T20：[MainWindow.xaml.cs](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 6,369 行；[MainWindowViewModel](../../src/NetBootDhcpTool.App/MainWindowViewModel.cs) 主要提供 ObservableCollection，窗口仍管理更新检查、测速、下载、取消、状态文本和关闭等待。
- 具体入口：`CheckForUpdatesAsync`、`UpdateVersionPresentation`、`FormatUpdateSpeedSummary`、`FormatUpdateSpeedDetails`、`DownloadUpdateAsync`、`UpdateDownloadProgressPresentation`、`CancelUpdateDownload_Click` 以及 `OnClosing` 的更新相关部分。
- [UiTests/Program.cs](../../src/NetBootDhcpTool.UiTests/Program.cs) 通过字符串反射设置 `_updateCheckStarted`、`_lastUpdateResult`、`_updateDownloadInProgress`、`_updateDownloadCts`；字段改名容易破坏测试。
- [VersionUpdateService](../../src/NetBootDhcpTool.Core/VersionUpdateService.cs) 已有可注入传输、双源校验、测速、下载回退与 SHA 保护，继续复用，不再实现另一套更新服务。

## 实现范围与步骤

1. 先列出现有更新状态转换和资源所有者，建立行为测试；抽取一个更新控制器负责检查/测速/下载、取消、任务跟踪与释放，一个轻量显示状态对象负责可观察字段。
2. MainWindow 仅保留按钮事件转发、用户确认/文件位置交互、绑定和提示展示；控制器不依赖 Window、Dispatcher、MessageBox 或具体控件。通过显式回调/接口传递状态并在 App 层调度 UI。
3. 使用构造注入传入更新服务、当前版本、目标路径提供器及进度接收器。纯状态/编排放在可被现有 UnitTests 引用的层；WPF 绑定适配放 App 层。不要为测试将私有业务字段全部改成 public。
4. 更新功能测试改用类型化构造/操作入口，删除这一功能相关的反射字段访问；保留真实按钮取消、状态显示和关闭等待的 UI 集成断言。无关恢复/路由反射测试留在原处，不扩大本任务。
5. 统一更新检查与下载的关闭责任：取消后观察任务结束，禁止迟到状态覆盖已关闭视图，再由唯一所有者释放服务/CTS。窗口网络工作流和恢复清理仍保持原顺序与责任。

## 边界与非目标

- 不把整个主窗口一次重写为 MVVM，不引入大型 DI/MVVM 框架；仅移动 partial 文件不算完成职责拆分。
- T23/T24/T25/T27 各自提取与本任务不同的探测、租约、历史、刷新责任；不要再建立一套通用后台任务调度系统。
- 保留 [T14](T14.md)/[T18](T18.md) 更新行为：两源中最新有效版本、64 KiB 测速、白名单 URL、SHA-256、30 秒源空闲回退、取消后可重试、低速只展示邮箱、绝不自动安装。T19 发布工作流和资产格式不改。

## 验收标准

- [x] 更新状态/取消/关闭测试无需实例化 MainWindow，无更新功能私有字段名反射依赖；UI 烟测仍操作实际按钮并断言显示。
- [x] 主窗口不再持有更新执行状态机和独立任务/CTS 所有权，所有权在控制器内明确；界面展示和业务协议不变。
- [x] 检查中关闭、测速中关闭、下载中取消/关闭、失败后重试、旧进度迟到均无资源泄漏或状态串写。
- [x] 现有 VersionUpdateSourceTests/VersionUpdateDownloadTests 和更新 UI 用例通过；默认测试零真实公网下载/发布。
- [x] 给出拆分前后职责与模块责任表和类型化测试入口证据；不用行数或类数作为唯一质量指标。
