# T26 会话日志写入与显示批处理

类型：运行效率与资源生命周期；优先级：P2；风险：中；接手：Luna。状态见[待办索引](../TODO.md)。

## 目标与源码证据

减少逐条日志的文件打开和 UI 调度成本，文件日志保持完整且可读取。

- 基线同 T20。[FileLogger.Write](../../src/NetBootDhcpTool.Core/Logger.cs) 每条日志在锁内调用 `File.AppendAllText`，之后触发 `LineWritten`；`Explain` 每次创建固定翻译前缀数组。
- [MainWindow](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 为每条日志 `Dispatcher.BeginInvoke`；`AppendLogLine` 每条创建 Paragraph、滚动并更新汇总。当前已经把显示限制为 500 个块，但尚未限制 Dispatcher 待处理数量。
- [App.OnExit](../../src/NetBootDhcpTool.App/App.xaml.cs) 记录退出后释放单实例锁；支持包会读取本次日志，必须兼容新的持有文件流。

## 实现范围与步骤

1. FileLogger 生命周期内持有一个受锁保护的写入器，保持带 BOM 的 UTF-8、唯一会话文件名和每条完整写入。继续逐条刷新写入器，让日志立即可读；本任务先消除反复打开/关闭文件，不引入异步文件日志队列或新的丢失窗口。
2. 流允许支持包只读共享；提供幂等 Dispose/Flush，正常退出最后一条日志写完并刷新后再释放文件和单实例锁。构造失败、异常退出处理器与关闭顺序不产生二次异常遮蔽根因。
3. 将固定翻译表移为静态只读数据，保留既有双语解释；避免日志接收者反向阻塞文件写入。文件错误要有非递归报告渠道，不能通过同一个已失败的 logger 无限记录错误。
4. 主窗口用具名订阅处理器把显示日志放入有界队列；最多保留最新 500 条待显示日志，每 100 ms 批量消费，整批只滚动和更新汇总一次。显示溢出可以丢弃最旧显示项，但必须提示省略数，完整文件不得丢弃。
5. 保持 UI 顺序与文件写入顺序一致；关闭时停止定时消费并取消订阅，避免窗口销毁后仍投递 Dispatcher。日志折叠时不做无意义排版，重新展开显示最近记录。

## 边界与非目标

- 不截断/删除会话文件，不改变支持包脱敏，不把 INFO/WARN/ERROR 过滤成文件丢失，不引入远端日志上传。
- 日志不是恢复事务存储；不要修改 JsonStore、DHCP ACK 或系统变更恢复时序。
- 不宣称写入器 Flush 等同断电持久化；保留当前及时可读的日志契约，不新增此保证。

## 验收标准

- [x] 10,000 条并发合成日志在文件内每条一次、完整可读；会话文件只建立一个持续写入器，最终关闭后没有文件句柄残留。
- [x] 文件带 BOM、中文/多行异常正常；支持包可以在应用运行时读取日志；会话文件用进程和 GUID 保证唯一。
- [x] UI 待处理数和显示块数有界，爆量时显示省略计数；单批至多一次滚动，取消自动滚动时不再调用滚动。
- [x] 关闭、重复 Dispose、写入失败、订阅异常均可控，失败时仍释放流并完成通知队列，没有递归日志异常或关窗后的 UI 回调。
- [x] T20 记录文件打开数及写入耗时；UI smoke 记录刷新批数、每批上限和队列峰值；完整文件内容与输入对应。
