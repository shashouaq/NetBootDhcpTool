# T04 损坏数据保护与有效备份恢复

类型：数据安全；风险：高；追溯：CODE-006、TEST-003。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

区分空数据与读取失败，阻止启动、导入或退出把尚可恢复的数据覆盖为空表或默认值。

- 证据：[FavoriteStore](../../src/NetBootDhcpTool.Core/FavoriteStore.cs) 读取失败会尝试 `.bak`，但最终失败仍返回空列表；`Save` 又删除备份。[Defaults.EnsureFiles](../../src/NetBootDhcpTool.Core/Defaults.cs) 将空列表当成缺少预设并保存。
- [ProfileStore.Load](../../src/NetBootDhcpTool.Core/ProfileStore.cs) 失败直接返回空列表，不读取有效备份。[JsonStore.LoadOrDefault](../../src/NetBootDhcpTool.Core/JsonStore.cs) 的回退也没有向调用者表达失败/恢复状态。
- 合成文件复现：损坏收藏被默认收藏替换且无备份；损坏方案存在有效 `.bak` 仍加载为零条。未读取或破坏真实用户收藏。

## 实现范围

允许调整上述存储接口、Defaults、App/主窗口的对应加载与保存调用，以及必要的加载结果模型。同步检查 settings、profiles、favorites、恢复记录的调用方，防止改接口后仍把错误当空值。

边界：保留当前文件位置、JSON 兼容、原子替换、个人凭据 DPAPI 和公共预设的明确标记。非目标：引入数据库、云同步、重写所有业务模型，或实现 T12 的编辑/导入策略。

## 业务规则与实现要求

- 读取结果至少可区分：文件不存在、有效空内容、有效数据、从备份恢复、损坏/读取失败；日志和 UI 能说明实际来源。
- 文件级默认初始化只在确实不存在时执行；已验证有效的数据可按既有规则升级预设，预设删除的持续性由 T12 处理。读失败、两份文件均损坏或权限不足时，不自动保存空值、生成默认收藏或删除原记录。
- 先验证主/备内容，再选最后有效内容；恢复时保留失败原件与有效备份，不因一次启动覆盖唯一恢复来源。
- 备份必须符合凭据保护要求：个人凭据以 DPAPI 保存，不产生新的明文密码副本；旧明文数据迁移/隔离处理后再保留安全备份，不能简单取消全部备份删除。
- 保存失败传播给业务调用者，不显示成功；退出不得将“未成功加载”的内存默认值覆盖到原文件。
- 对其他 JSON 调用者限定兼容改动，分别验证迁移与回退，不顺带改动业务数据内容。

## 验收标准

- [x] 主文件损坏、有效备份存在：恢复正确内容并提示来源；主备均坏：保留原件且不自动覆盖。
- [x] 首次启动和合法空列表仍按各自业务规则工作，不能把合法空列表误判为读取失败。
- [x] 拒绝访问、磁盘写入失败、替换失败和中途异常不会破坏最后有效版本，也不会显示保存成功。
- [x] 个人凭据迁移、DPAPI 不可解密时的非凭据数据保留、公共预设和历史 JSON 均不丢非凭据数据；安全备份不含个人明文密码。不可解密分支以 DPAPI 保护值不可还原的回归覆盖，未在第二个 Windows 身份下做端到端登录测试。
- [x] 恢复日志无法读取时不将其当成“无需清理”，用户可见待恢复问题；UI 烟测验证警告、写入锁定及主备文件保留。
