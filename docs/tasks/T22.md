# T22 合并路由规划的只读查询

类型：运行效率；优先级：P1；风险：中；接手：Luna。状态见[待办索引](../TODO.md)。

## 目标与源码证据

减少路由预览与应用准备中的进程启动和重复 Windows 查询，同时继续使用本次操作的新鲜状态。

- 基线同 T20。[StaticRouteService.PreparePlanAsync](../../src/NetBootDhcpTool.Network/StaticRouteService.cs) 依次等待 `GetCurrentStaticRoutesAsync`、`GetInterfaceMetricsAsync`、`GetInterfaceStatesAsync`、`GetInterfaceAddressesAsync`，共四次 PowerShell 调用；前三个查询分别读取 `Get-NetIPInterface`。
- `PreviewAsync` 和 `ApplyAsync` 都重新规划；`CreateRouteAsync`、`GetExactRoutesAsync`、`RemoveAsync` 另有写前/归属检查，不能随批量读取一起删除。
- [T17](T17.md)只优化启动的网卡/路由两项并行，不覆盖规划内部这四次读取。

## 实现范围与步骤

1. 增加一次操作内的强类型只读快照：路由、接口跃点、接口连接状态、地址。单个脚本只读一次 `Get-NetIPInterface`，从同一结果投影跃点和状态；再读取路由与地址，输出一个结构化 JSON 对象。
2. 让 `PreparePlanAsync` 每次重新获取该快照；启动只展示路由的入口继续按需要读取，避免为它加载无用地址信息。不要跨刷新、预览、应用复用旧快照。
3. 明确空数组与失败的区别；字段缺失、查询失败、部分 JSON 不得被解释为“没有冲突”。IPv4/IPv6、Protocol 字符串、PolicyStore、InstanceId 和现有排序/跃点规则均保留。
4. 规划消费一致结构，但不能声称 Windows 多项查询具有事务原子性。应用仍重新规划，每个写入继续在系统侧检查稳定 GUID、精确冲突和读回身份，逐条记录意图、归属与回滚结果。
5. 使用同一组生成脚本的 cmdlet 替身和 T20 夹具做前后对比，统计进程调用与查询次数；实机只读采样比较中位数，单独记录应用/清理回归。

## 边界与非目标

- 不合并路由写入与清理事务，不增加缓存 TTL，不省略默认路由拒绝、下一跳同链路、重叠路由或归属检查。
- 不修改 T01/T05/T08 的 DHCP、网卡与防火墙流程；不为缩短 DHCP 启动时间删除系统读回。
- 不用四个不受控并行进程替代四次串行进程，也不重写 Windows 路由 API。

## 验收标准

- [x] 一次 `PreparePlanAsync` 的快照读取由四次进程调用变为一次，`Get-NetIPInterface` 由三次变为一次；写前/精确归属查询另计并保留。
- [x] 合成空/单条/多条 IPv4/IPv6 数据生成与旧版等价的计划、跃点赢家、冲突和状态；任一读取失败即阻止应用。
- [x] 在预览后改变系统替身状态，应用读取新状态并拒绝新冲突；接口 index 复用仍拒绝写入。
- [x] 用户取消后没有剩余读取任务；创建中断、恢复日志失败和回滚仍留下准确的逐条记录。
- [x] T20 前后报告给出读取耗时及调用数；没有将历史 T17 数据当作本次提速证明。
- [x] 在 UTF-8 输出修复后的最终 Release 产物上重新通过管理员 Hyper-V 路由烟测，并确认所有临时资源清洁。
