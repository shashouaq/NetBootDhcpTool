# T14 更新下载最终落盘

类型：缺陷修复；风险：中；追溯：CODE-008、TEST-003、MAINT-002。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

合法更新包下载并通过校验后能够安全落盘；失败、取消与重试不损坏已有目标文件，完整流程可离线测试。

- 证据：[VersionUpdateService.DownloadAsync](../../src/NetBootDhcpTool.Core/VersionUpdateService.cs) 的 `hashInput` 以 FileShare.Read 打开，在释放之前执行 File.Move；Windows 相同文件操作模式复现 IOException `0x80070020`。
- 下载方法自己创建 HttpClient，未复用版本检查的可注入依赖，现有测试难以覆盖下载→校验→移动。审计未实际下载远端版本，不能把模拟结果写成远端下载验收。
- UI 入口在 [MainWindow](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 的新版本点击及后台下载路径。

## 实现范围

允许修改校验流生命周期、最终文件替换、临时文件清理、下载传输注入，以及必要的 UI 失败/取消结果和测试。

边界：保留 HTTPS GitHub Release URL 限制、合法 SHA-256 校验、下载前展示更新内容、用户选择与无自动安装。非目标：自动升级/执行下载文件、发布新版本、签名体系、邮件发送或增加下载源。

## 业务规则与实现要求

- 写入、读取校验和移动分阶段释放句柄；校验成功且所有文件句柄关闭后才替换目标。
- hash 不匹配、网络失败或取消不得覆盖已有有效文件；临时文件清理结果明确且不删除与本次下载无关文件。
- 复用可注入的 HTTP 传输，正确区分调用方和服务拥有的客户端生命周期；测试不得为绕过 URL 校验而降低生产校验。
- 替换失败（目标被锁、权限不足等）给出可重试结果；避免并发点击操作同一 `.download` 路径，遵守现有操作所有权。
- 进度和低速提示保持既有业务边界：只显示联系邮箱，不自动发送；错误与取消不能显示下载成功。

## 验收标准

- [x] 离线模拟的正确包完成下载、SHA-256 校验和最终移动，目标哈希正确且临时文件按规则处理。
- [x] 校验不匹配、HTTP 错误、读流失败、取消和磁盘异常均保留原目标，重试可成功。
- [x] 目标已存在、目标被锁、重复点击以及文件流释放时点都有明确行为，无自身共享冲突。
- [x] 非法 URL/哈希仍在下载前拒绝；下载完成不运行安装、不发送邮件。

## 测试与回归要求

- 使用 Fake HttpMessageHandler、有效格式的允许域名 URL 和临时目录，测试整个 DownloadAsync；断言文件内容、哈希、句柄释放、旧文件保留和临时文件状态。
- 用可控制的读流模拟取消、读错误和进度；Windows 回归先证明哈希读句柄未关闭时移动失败，再证明 DownloadAsync 在所有句柄关闭后替换成功。
- 回归版本解析、manifest 校验、发布说明展示、无更新/检查失败、下载前确认、取消重试及支持包脱敏。
