# T03 网络操作互斥与取消责任

类型：业务完整性；风险：高；追溯：BIZ-001、TEST-001、TEST-004、MAINT-001。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

让 DHCP、手动配置/扫描、恢复、路由、重启/MAC 和退出遵守同一操作约束，取消只影响被取消的操作。

- 证据：[MainWindow](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 的 `SetDhcpRunningState`、`UpdateManualScanButtons`、`ApplyAndScanAsync` 没有共同门禁；DHCP 运行时手动应用仍可用，隔离 UI 状态已复现。
- [RestoreRecoveryEntryAsync](../../src/NetBootDhcpTool.App/MainWindow.Recovery.cs) 未统一检查安全入门锁及冲突操作；`SetBusy` 管理全局 CTS，刷新快捷键可能启动新操作并取消旧操作。
- 这是本机操作安全约束，不是新增角色或账户权限系统。

## 实现范围

允许有限提取操作状态/所有者/取消编排，调整主窗口和恢复中心的按钮、命令及快捷键校验，补自动化测试。边界：保留现有安全确认、只读浏览、正常取消反馈和可重试恢复。非目标：全面 MVVM 改造、新建 RBAC 或为所有只读操作加阻塞锁。

## 业务规则与实现要求

- 同一时刻最多一个网络修改工作流；DHCP 运行期间不得再执行手动应用、恢复、路由写入、重启或 MAC 修改。先停止并完成必要清理，再进入下一个操作。
- 扫描运行期间禁止重复启动和收藏应用；需要切换工作流时先取消并等待原操作及补偿完成。
- 只读模式允许查看恢复项；真正恢复必须先通过现有安全向导显式解锁，并确认恢复。单次恢复确认不能绕过安全锁。
- 每个操作持有自己的 CTS；新操作不得隐式取消旧操作，取消不得撤掉补偿令牌。关闭窗口须等待运行任务结束/补偿后执行退出清理。
- 外部刷新和快捷键不得重入正在变更的网络状态；同一操作内部的只读回读应复用所有者上下文，避免死锁。
- 按钮禁用只是提示，执行函数仍校验门禁；失败、取消和异常结束必须释放正确所有者，不释放其他操作的锁。
