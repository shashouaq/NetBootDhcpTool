# T09 DHCP 协议、租约与检测状态

类型：业务完整性；风险：高；追溯：BIZ-002、TEST-002。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

依据客户端状态正确应答，区分活动租约、历史会话和连通性，既有 DHCP 预检测只能依据本次探测的有效响应作判断。

- 证据：[DhcpServer.LoopAsync](../../src/NetBootDhcpTool.Dhcp/DhcpServer.cs) 对全部 Request 调用 Allocate 并 ACK；[DhcpPacketParser](../../src/NetBootDhcpTool.Dhcp/DhcpPacketParser.cs) 未校验 cookie/op/htype/hlen，未解析并使用 Server Identifier。
- 回环复现：发给其他服务器、请求 `.199` 的 Request 被 ACK 为 `.100`；错误 cookie/op/hlen 的 Discover 仍获 Offer。RELEASE、DECLINE 无处理分支。
- [DhcpLeaseManager](../../src/NetBootDhcpTool.Dhcp/DhcpLeaseManager.cs) 每次服务启动重新创建；[主窗口租约探测](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 保留旧行并按旧 IP Ping，可能混淆新使用者。
- [ExistingDhcpDetector](../../src/NetBootDhcpTool.Network/ExistingDhcpDetector.cs) 和 [DhcpVerifier](../../src/NetBootDhcpTool.DhcpVerifier/Program.cs) 需核查首包处理、事务匹配和报文边界；预检测当前只等第一个包。

## 实现范围

允许修改报文模型/解析/回复、租约状态与必要持久化、服务状态机、预检测/验证器，以及租约 UI 的当前/历史表达和测试。

边界：继续提供隔离 IPv4 调试用途、已验证的选定接口约束和有限地址池。非目标：DHCPv6、Relay、HA、企业预留管理、无限期租约数据库或全协议扩展。实现依据 [RFC 2131 §4.3](https://www.rfc-editor.org/rfc/rfc2131.html#section-4.3)，不能直接把 Discover/Request 都当成已承诺租约。

## 业务规则与实现要求

- 严格校验必要报文头、cookie、选项长度和客户端身份；畸形/不支持报文不分配租约、不抛出循环外异常。
- 区分 SELECTING、INIT-REBOOT、RENEWING/REBINDING；选择其他服务器不 ACK，选择本服务器时 ACK 地址必须符合请求与有效绑定，不满足时按协议 NAK 或忽略。
- Offer 预留与已确认租约分开；未获 Request 的预留可过期。重复 Discover/Request 对相同客户端幂等，不能耗尽多个地址。
- 验证 RELEASE 的客户端/地址归属后释放；DECLINE 标记冲突地址不可用。租约和冲突隔离到期逻辑可注入时钟，重复报文不错误释放他人租约。
- 停止/重启时处理尚未过期绑定，不能仅清空 UI 就认为不会重复分配；采用可验证的绑定保留或冲突检测策略，必要的小型状态文件使用 T04 的恢复语义。
- 当前租约、历史会话和 Ping 在线状态分开，IP 复用不得让旧 MAC 显示为新设备在线；最后在线时间只在不可达→可达时更新。
- 预检测在总超时内持续丢弃无关包，匹配 xid、客户端身份及有效 Offer；错误包先到不能直接返回“没有 DHCP”。诊断工具遵守相同边界但保持独立用途。

## 验收标准

- [x] 选择本/其他服务器、请求旧地址、不匹配地址、续租、释放、冲突、过期及重复报文各有明确正确结果。
- [x] 畸形/截断选项和非法头不产生 Offer/ACK，不改变池状态；合法后续客户端仍可正常工作。
- [x] 重启后未过期地址不会不加处理分给其他客户端；旧会话行不会冒充当前租约或借用新客户端 Ping 状态。
- [x] 无关首包后有效 Offer 仍被预检测识别；错 xid/MAC、伪类型或超时不会得到错误结论。
