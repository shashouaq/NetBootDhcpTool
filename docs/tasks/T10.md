# T10 预览和测试脚本安全退出

类型：工程安全；风险：高；追溯：CODE-011、TEST-001。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

预览、构建和打包辅助脚本不能中断应用的网络恢复，也不能终止其他工作目录的同名进程。

- 证据：[run-app-admin.ps1](../../build/run-app-admin.ps1) 按进程名取得所有实例，`CloseMainWindow` 后只等 5 秒，且将默认无输出的 `Wait-Process` 当布尔值判断，再执行 `Stop-Process -Force`。
- [MainWindow.CleanupWorkEnvironmentAsync](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 有多个独立、有超时的串行清理步骤，5 秒不能代表清理完成。
- [stop-test-processes.ps1](../../build/stop-test-processes.ps1) 注释声称仅停止本仓库测试，实际按名称和命令行匹配，没有检查仓库绝对路径。以上由脚本链确认，未强杀实际应用验证。

## 实现范围

允许修改上述两脚本及必要的构建/发布调用参数，新增针对脚本的隔离测试和维护说明。边界：预览优先当前源码 Release 输出、再回退已打包输出；GUI 运行时打包仍拒绝；PktMon 等机器级状态不由这些脚本清理。

非目标：增加默认强杀选项、结束其他目录/用户进程、自动绕过 UAC、重写发布流程或改变应用网络恢复业务。

## 业务规则与实现要求

- 解析实际可执行路径/命令行参数并与本仓库允许目录规范化比较，不能用进程名或路径子串证明归属；路径不可读时保守跳过/报告。
- 发出正常关闭请求后用真实退出状态等待，允许时间应覆盖应用串行清理上限；取消关闭、超时或无法确认退出时失败返回并保留原进程。
- 只有前实例确认退出后才启动新预览；不自动强杀承担恢复责任的进程，不并发新旧 GUI。
- 测试清理只结束能证明由当前仓库测试入口创建的进程；不动独立诊断捕获、其他目录测试或其他工具。
- 若 T02 的单实例阻止新启动，展示已有实例信息，不能通过强杀绕过所有权。

## 验收标准

- [x] 模拟清理持续超过 5 秒，脚本等待其完成后再启动；超时/拒绝关闭时没有 Force 杀进程和新 GUI。
- [x] 默认无输出的 Wait-Process 不再导致错误分支，进程提前退出和已退出对象均正确处理。
- [x] 不同目录同名 GUI/测试、带空格路径、不可读路径不会被误终止；当前仓库目标识别准确。
- [x] 打包依旧拒绝运行中的 GUI，当前源码预览选择及发布输出回退不变。

## 测试与回归要求

- 用临时目录和测试专属子进程模拟慢退出、超时、拒绝关闭、提前退出与路径冲突；对实际脚本行为断言启动时序和存活进程，不只检查脚本文本。
- 覆盖当前支持的 PowerShell 版本和 `.exe`/`dotnet` 入口；环境不可用需记录。测试自身不得调用真实网卡工具或结束现有应用。
- 回归 build/publish/clean 对测试清理的调用、源码预览/打包回退、UAC 启动和 T02 单实例行为。

## 依赖、文档同步与完成条件

硬前置：[T02](T02.md) 的进程/数据所有权契约；与 [T03](T03.md) 对齐退出完成时点。脚本可独立修复，但完整退出联调应覆盖 T01/T05/T06/T08。

同步 MAINTENANCE_GUIDE、RELEASE_PROCESS 中实际进程边界及超时处理说明，记录 FEATURE_CHANGELOG。隔离脚本测试、调用链回归和文档均通过才可完成；不得通过运行真实强杀命令取得验证证据。

## 2026-09-25 回归补充

真实预览前检查发现，`Get-NetBootRunningAppProcesses` 用一元逗号返回空数组时会把它包装成一个空对象；无应用运行时，`Assert-NetBootNoRunningApp` 因而错误拒绝后续操作。已修正两个同名定义的返回方式，并在隔离脚本测试中覆盖“只有无关 dotnet 测试入口、没有 GUI”的场景。Windows PowerShell 5.1.26100.9549 与 PowerShell 7.6.5 均通过 `PROCESS_SAFETY_OK`。现有 GUI 仍只允许按已验证归属正常关闭；未运行强制终止。
