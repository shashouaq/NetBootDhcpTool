# T17 并行读取启动网络快照

类型：性能优化；风险：低。状态见[待办索引](../TODO.md)。

## 目标与现状

缩短启动和手动刷新时的适配器/当前路由发现等待。T16 的实测日志记录适配器枚举 847 ms、当前 IPv4/IPv6 路由读取 3,583 ms，两项串行完成，网络发现总计约 4,441 ms。

## 实现范围

- 并行启动只读的网卡枚举和当前 IPv4/IPv6 路由查询；界面仍等待两项结果，再按原有顺序更新适配器选择和路由列表。
- 保留手动刷新、恢复流程和路由列表的现有入口；路由预览、应用、清理仍执行各自的实时状态和归属校验。
- 记录当前路由查询耗时及并行网络发现总耗时，供后续定位仍然较慢的阶段。
- 在任何一个读取先失败时，仍观察另一项后台任务的完成/异常，避免未观察的任务异常。

## 业务边界与非目标

- 不缓存快照，不展示上一次读取结果冒充当前状态；不改变 DHCP、网卡、MAC、路由或防火墙操作。
- 不跳过适配器/路由验证、用户确认、变更顺序、读回校验、回滚、取消或恢复步骤。
- 本任务优化启动/刷新中的只读发现等待；不宣称网卡写入、DHCP 启停或退出恢复本身变快。
