# T01 固定 DHCP 会话恢复对象

类型：缺陷修复；风险：高；追溯：CODE-001、TEST-001、MAINT-001。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

只恢复实际参与 DHCP 会话的原网卡，不能因停止、选择变化、拔插或索引复用而修改另一张网卡。

- 证据：[MainWindow.xaml.cs](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 的 `StopDhcp_Click` 清空 `_activeDhcpAdapterIndex`，`CleanupWorkEnvironmentAsync` 仍依据 `_dhcpWasStartedInThisSession` 恢复；`GetDhcpRestoreAdapter` 会回退到 `SelectedAdapter`。
- `RestoreOriginalAdapterConfigAsync` 按接口索引取快照，找不到快照时执行 `RestoreDhcpAsync`。已有 [AdapterIdentityMatcher](../../src/NetBootDhcpTool.Network/AdapterIdentityMatcher.cs) 和 [恢复中心](../../src/NetBootDhcpTool.App/MainWindow.Recovery.cs) 的稳定身份机制可复用。
- 隔离复现：A 会话停止后选中 B、或者 A 消失，两种情况下恢复目标均变成 B；未执行真实网卡写入。

## 实现范围

允许修改 DHCP 会话身份/恢复责任、停止与退出编排、必要的现有备份模型适配，以及对应测试。定位 `RememberAdapterConfigAsync`、`GetDhcpRestoreAdapter`、`RestoreOriginalAdapterConfigAsync`、`CleanupWorkEnvironmentAsync`。

边界：保留停止时恢复开关、正常退出清理和恢复中心逐项确认；重用稳定身份匹配。非目标：改写 IPv4 快照内容、DHCP 协议或全面拆分 MainWindow，分别由 T05、T09 负责。

## 业务规则与实现要求

- 启动前记录不可随 UI 选择变化的原网卡身份和原快照；接口索引只能用于当次系统调用，不能独立证明身份。
- 恢复责任必须区分尚未修改、已修改待恢复、恢复成功和恢复失败。验证成功才消除责任；失败保留记录供重试。
- 原网卡不可用、身份冲突、快照缺失时停止自动恢复并提示，禁止改用当前选中网卡或猜测启用 DHCP。
- 停止已成功恢复后退出不得再次修改网卡；停止时选择不恢复的会话，在正常退出时仍按原会话对象完成既有清理要求。
- 自动恢复发现外部配置已改变时保留冲突记录，不静默覆盖第三方修改；明确人工恢复入口。

## 验收标准

- [ ] A 启动、停止、选择 B、退出：B 的 IP、DNS、路由、跃点和 MAC 不发生写入。
- [ ] A 拔除、索引被 B 复用、名称变更、重复启停及多张网卡先后使用时，均只定位有责任的原对象。
- [ ] 无快照或身份不匹配时没有回退写入，用户可见失败和待恢复原因。
- [ ] 恢复成功后重复停止/退出不产生第二次修改；失败后重试可继续完成且历史结果准确。
