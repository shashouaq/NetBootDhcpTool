## 目标与当前问题

在现有文档体系上减少重复和冲突，让新会话能从入口、单个任务和相关代码理解工作；用户说明必须符合实际实现和已验证边界。

- 证据：[PROJECT_MEMORY](../../PROJECT_MEMORY.md) 的 Change and publication boundary 要求每次修改构建/预览，[MAINTENANCE_GUIDE](../MAINTENANCE_GUIDE.md) 已允许纯文档轻量检查；PktMon 清理要求也存在不同表述。
- PROJECT_MEMORY/维护指南写更新摘要来自 Unreleased；[publish.ps1](../../build/publish.ps1) 实际优先当前版本章节，[RELEASE_PROCESS](../RELEASE_PROCESS.md) 已准确描述该优先级。发布命令在多文档重复。
- [单页指南](../NetBootDhcpTool_OnePageGuide.html) 仍为 v1.0.10；[Wi-Fi 排障文档](../troubleshooting/windows-wifi-wired-conflict.md) 的笼统“永不修改 Wi-Fi”与独立授权的重启/MAC 例外不一致。
- [AppSettings](../../src/NetBootDhcpTool.Core/Models.cs) 的 AllowDhcpOnWifi 及主窗口开关允许用户启用，网络服务仍无条件拒绝 DHCP/手动 IPv4 修改 WLAN，形成无效承诺。
- 本轮仅建立 [待办索引](../TODO.md)、任务正文和阅读入口；这些不代表上述治理或配置修复已完成。原有三份未提交文档修改必须保留并合并。

## 实现范围

文档限 README、PROJECT_MEMORY、现有维护/发布/变更/发行说明、单页指南、排障文档及 TODO/tasks 的必要引用；检查工具只在能稳定验证新增一致性规则时小范围扩展 [verify-maintenance.ps1](../../build/verify-maintenance.ps1)。

配置改动仅限弃用无效的 AllowDhcpOnWifi 开关及对应 Models、MainWindow、Defaults/i18n、帮助和兼容测试；不能把治理任务扩大成网络功能开发。

边界：保留用户要求的发布授权、双语 UI、恢复安全和已有文档资产。非目标：强制新建 AGENTS/Architecture/BusinessRules 等平行规范、翻译两套相同维护命令、改写历史版本事实或开放 Wi-Fi DHCP。

## 业务规则与实现要求

- 权威职责：README 管项目定位/启动/阅读入口；PROJECT_MEMORY 管稳定业务边界；MAINTENANCE_GUIDE 管开发流程及验证选择；RELEASE_PROCESS 管唯一发布步骤；FEATURE_CHANGELOG 管已发生变更；TODO 管待办状态，任务正文管范围和验收；用户指南只表达可使用行为。
- 同一规则只在权威文件维护，其他位置用链接；删除重复前核对其中独有的约束和验证信息，不能为了缩短删掉边界。
- 当前源代码/可验证行为优先说明实现现状；待办目标与历史验证不能写成当前已实现。T01～T14 未验收的限制要有准确链接，不能用文案宣称修复。
- 纯文档不要求应用预览，机器级 PktMon 不属于打包自动清理范围；进程清理说明必须等待 T10 实现后再作相应保证。
- 维护指南引用发布流程，不再维护重复命令；发行说明可保留用户摘要，哈希、完整日志等证据引用变更记录，避免重复事实源。
- 单页指南版本与应用版本一致；重启/MAC 设置的独立 Wi-Fi 例外写清。移除/弃用无效 DHCP Wi-Fi 开关，旧 JSON 的 true 必须兼容读取但不得成为新增授权；其他安全开关含义不变。
- 保持 TODO 索引短小，执行者只需入口和目标任务；完成状态只在索引维护，完成证据链接变更日志，不再保存整份审计副本。
