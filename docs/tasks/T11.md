# T11 扫描范围限制与统一校验

类型：可靠性；风险：高；追溯：CODE-009、TEST-004、MAINT-002。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

在修改网卡之前确定合法且有界的探测范围，扫描准备和执行都可取消，收藏应用与手动入口遵循同一规则。

- 证据：[PingScanner.ScanAsync](../../src/NetBootDhcpTool.Network/PingScanner.cs) 在首次 await 前将全部 Hosts 再转成列表；[IpNetwork.Hosts](../../src/NetBootDhcpTool.Core/IpNetwork.cs) 本身完整创建地址集合，合法 `/8`、`/0` 可导致巨大分配。
- [MainWindow](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 的 `IsValidFavorite`、`ApplyFavorite_Click`、`ApplyAndScanAsync`、`UpdateManualScanButtons` 的校验不一致；非空无效目标可能落入全网段分支。
- `PingScanner.ResolveHost` 及目标探测包含阻塞式 DNS 调用，需与取消/时限一起处理。调用链确认；未进行大网段或办公网扫描。

## 实现范围

允许增加共享执行前校验/范围计划，调整 IpNetwork 枚举、PingScanner、主窗口和收藏应用入口，以及必要的本地化/帮助和测试。

边界：收藏“加载”仍只填字段，“应用并扫描”仍只执行一次配置和扫描；单目标持续探测、HTTP/HTTPS 正常证书验证、网卡高跃点/无网关 DNS 策略不变。非目标：高速全网发现、ARP/SNMP、新增后台计划扫描。

## 业务规则与实现要求

- 先解析并验证 IPv4、连续掩码、可用主机及目标范围，再做网卡修改；所有按钮、收藏和方案来源进入同一执行前校验，禁用按钮不能代替服务规则。
- 非空目标必须合法并满足当前同网段约束；非法目标明确拒绝，不能扩大成全网段。空目标才表示网段扫描。
- 工程默认上限为 4096 个实际探测地址（排除本机及该前缀规则下不探测的地址）；用统一命名常量计算并在预览/错误中表达。超过上限在写入网卡前拒绝，本任务不增加强制绕过入口。
- 地址数量用安全整数计算，不先枚举再比较；扫描使用有界、可取消的枚举/分批与并发控制，禁止在 UI 线程生成巨大列表。
- DNS 解析移出 UI 线程并设置有界等待；取消后停止排队新探测、尽快结束等待，不残留持续增长的后台任务。
- `/31`、`/32`、非连续掩码、网络/广播地址等边界有明确结果和测试，不依赖溢出或偶然空列表。

## 验收标准

- [x] `/8`、`/0` 等超限输入快速拒绝，网卡执行器调用次数为零，内存不随总地址数增长。
- [x] 恰好达到上限可执行，超过上限拒绝；不同入口得到同一范围和错误，预览数量与实际目标一致。
- [x] 非空无效目标不扫描网段；合法单目标只探测该地址，收藏应用无重复配置/扫描。
- [x] 枚举、Ping、HTTP、DNS 各阶段取消均不会冻结 UI，状态和历史正确回到已停止/失败。

## 测试与回归要求

- 单测覆盖范围计数、边界掩码、上限前后、溢出、入口校验一致性；用替代配置执行器证明非法输入在系统写入前被挡住。
- 受控探测器模拟慢 DNS、超时、取消、部分响应，断言有界并发和没有新任务继续产生；不对真实大网段发包。
- 回归单目标持续扫描、普通 `/24`、收藏加载/应用、方案导入后应用、进度/ETA、结果过滤及 T03 工作流互斥。
