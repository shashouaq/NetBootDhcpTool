# T18 Gitee 分发与自适应更新下载

类型：发布分发与更新可用性；风险：中。状态见[待办索引](../TODO.md)。用户已明确授权本次提交、推送和正式发布。

## 目标

为中国大陆用户提供 Gitee Release 下载，同时保留 GitHub 镜像；更新时探测每个可用来源并优先选择实测较快的一端，下载过程中持续展示速度和来源。

## 实现范围

- 应用先读取公开 Gitee 最新稳定 Release 和 `latest.json`；Gitee API、Release、附件或清单失败时回退 GitHub `latest.json`。
- 确认发现新版后，并行请求各来源最多 64 KB 的 Range 数据，逐源刷新测速状态；成功的来源按实测速率从快到慢排序，测速失败的来源排在后面，全部失败时保留清单原顺序。
- UI 在版本链接旁显示各源速度与首选来源，鼠标提示和确认框列出详细结果；下载状态按秒显示实时速度及正在使用的源，来源失败时显示已切换到镜像。下载后仍需 SHA-256 匹配才替换文件，不自动安装。
- GitHub 与 Gitee 的 `latest.json` 都包含两端下载地址，即使其中一端的更新检查 API 暂时不可达，也能测速并比较另一端的附件。
- GitHub 稳定 Release 发布触发 Actions；同一工作流也允许手动指定既有稳定标签重试。它校验发行资产，非强制 fast-forward 同步 `main` 和标签，创建/更新 Gitee Release，上传 `.7z`、`.sha256`、`latest.json`，读回并比较归档哈希，再更新并读回 GitHub 双源清单。
- Gitee Token 仅保存在 GitHub Actions Secret `GITEE_TOKEN`；桌面应用不接触凭据。

## 边界

- 不强推 Gitee 分支、不改写已有远端历史。若 Gitee `main` 不能快进，工作流失败并保留现状。
- 只接受本项目仓库的 HTTPS Release 页面与附件地址。任一镜像失败或哈希错误会清理该次临时文件，再尝试下一个批准来源；只在哈希通过后替换下载目标。
- Gitee 仓库保持公开；更新包不自动安装。
