# T06 静态路由清理与创建记录

类型：缺陷修复；风险：高；追溯：CODE-003、TEST-001、MAINT-002。状态见 [待办索引](../TODO.md)。

## 目标与当前问题

准确删除本工具拥有的临时路由，并保证创建后任一失败点都有可追踪的补偿或待核实记录。

- 证据：[StaticRouteService.RemoveAsync](../../src/NetBootDhcpTool.Network/StaticRouteService.cs) 计算 C# `policyStore`，却未向脚本赋值 `$policyStore`；后续校验使用该变量。模拟正确归属路由仍报 `Owned route parameters changed; refusing to remove it`。
- `CreateRouteAsync` 先 `New-NetRoute`，再查询/解析结果；`ApplyAsync` 仅在方法完整返回后加入回滚列表，存在修改成功但未记入列表的窗口。
- [MainWindow.SaveStaticRouteSession](../../src/NetBootDhcpTool.App/MainWindow.xaml.cs) 保存失败仅写日志；检查 `ClearAppliedRoutesAsync`、恢复中心和退出清理的逐条结果保存及取消路径。

## 实现范围

允许修改路由脚本生成/执行、创建计划与归属记录、主窗口路由生命周期、[AppliedStaticRoute](../../src/NetBootDhcpTool.Core/Models.cs) 的必要兼容字段及路由测试。

边界：不覆盖既有路由，不删除身份/参数已改变的对象；维持 IPv4/IPv6、直连/网关、默认路由禁止、同前缀不同接口和自动跃点规则。非目标：重新设计路由优先级算法、操作其他程序路由、增加持久路由功能。

## 业务规则与实现要求

- 修正所有脚本参数赋值并测试真实生成脚本；路由不存在时重复清理应安全成功，不把 Get-NetRoute 的无结果异常误判为已修改对象。
- 修改前写入创建意图，修改后回读 InstanceId/接口稳定身份/下一跳/跃点/PolicyStore 并持久化归属；日志失败必须影响结果。
- 意图记录不等于删除权限。创建后回读失败或崩溃时，依据可证明的前后状态确认归属；无法证明则保留待核实记录，禁止猜测删除同路径路由。
- 批量操作逐条记录结果；失败按反序尝试补偿。删除、补偿或保存失败保留剩余项，不宣称整批已回滚。
- 清理验证缺失后逐条更新记录；取消后再次启动能安全重试，不能因为空内存列表删除尚未处理的日志。

## 验收标准

- [x] 正确归属路由可删除；重复删除安全；实例标识、跃点或存储范围改变时拒绝误删。
- [x] 创建成功后查询失败、JSON 解析失败、记录写入失败、部分批次失败/取消及异常退出均有确定恢复结果。
- [x] 同前缀不同接口只清理本次创建对象；预先存在或第三方新建的路由保持不变。
- [x] 下一次启动、恢复中心和正常退出沿用同一归属规则；清理失败可列出具体失败项和真实剩余数量。
